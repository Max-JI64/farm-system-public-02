# 새 머신러닝 학습 계획

## 1. 목적

이번 머신러닝은 기존 `jsw/Analysis/machine_learning` 결과를 이어서 튜닝하는 작업이 아니다. 시간 누수를 수정하고 요인점수를 제거한 새 데이터에서 분할, 피처셋, 모델, threshold를 처음부터 다시 설계한다.

- 학습 데이터: `data/학습데이터/최종_머신러닝_학습데이터.csv`
- 데이터 설명: `jsw/Analysis/new_machine_learning/최종_머신러닝_학습데이터_설명.md`
- 변수사전: `jsw/Analysis/new_machine_learning/최종_머신러닝_변수사전.csv`
- 작업 위치: `jsw/Analysis/new_machine_learning`

최종 목적은 단순한 산불 발생/비발생 이진 판정이 아니라 다음 두 기능을 갖춘 산불위험 선별 모델을 만드는 것이다.

1. 실제 산불 표본을 가능한 한 많이 포착한다.
2. 한정된 점검 자원으로 우선 확인할 고위험 위치를 순위화한다.

산불을 놓치는 오류인 `FN(False Negative)`의 비용을 가장 크게 본다. 따라서 기본 운영점은 recall 70% 이상을 목표로 하고, recall 90% 운영점도 함께 제공한다.

다만 recall만 최대화하면 모든 표본을 산불로 예측하는 모델도 recall 100%가 된다. 이것은 실용적인 모델이 아니다. 따라서 recall 목표를 충족하는 범위 안에서 precision을 높이고 경보 대상 비율을 낮추는 방식으로 모델과 threshold를 선택한다.

## 2. Threshold에 따른 recall과 precision 비교가 맞는가

맞다. 모델은 각 표본에 산불위험 점수 또는 확률을 출력하고, threshold 이상을 산불 고위험으로 판정한다.

| threshold 변화 | recall | precision | 고위험 판정 수 | 해석 |
| --- | ---: | ---: | ---: | --- |
| 낮춤 | 증가 | 일반적으로 감소 | 증가 | 산불을 덜 놓치지만 오경보 증가 |
| 높임 | 감소 | 일반적으로 증가 | 감소 | 오경보는 줄지만 산불 누락 증가 |

주요 지표는 다음과 같다.

```text
Recall = TP / (TP + FN)
Precision = TP / (TP + FP)
```

- `TP`: 실제 산불을 산불 고위험으로 포착
- `FN`: 실제 산불을 비발생으로 놓침
- `FP`: 실제 비발생을 산불 고위험으로 경보
- `TN`: 실제 비발생을 비발생으로 판정

이번 과제에서는 `FN`을 줄이는 것이 우선이다. 그러나 threshold를 지나치게 낮추면 점검 대상이 과도하게 늘어나므로 다음 두 값을 반드시 함께 제시한다.

- `precision`: 경보 대상 중 실제 산불 표본 비율
- `selected_rate`: 전체 표본 중 경보 대상으로 선택된 비율

따라서 운영 결과는 “recall 70%”만 보고 끝내지 않고 다음처럼 보고한다.

> recall 70%를 확보하기 위해 전체의 몇 %를 경보 대상으로 지정해야 했으며, 그중 실제 산불 비율은 몇 %인가?

현재 데이터는 실제 운영 모집단을 그대로 센 것이 아니라 Target 0을 의도적으로 추출한 case-control 형태다. 따라서 개발·lockbox의 precision과 selected rate는 현재 샘플 구성에서의 비교값이다. 실제 전신주 또는 강원도 전체 후보 위치에 적용했을 때의 precision과 경보 비율은 별도의 운영 모집단 시뮬레이션으로 다시 계산해야 한다.

## 3. 기존 머신러닝에서 유지할 점과 변경할 점

### 3.1 유지할 점

- AUPRC, AUROC, Brier score, log loss를 함께 사용한다.
- threshold별 recall, precision, specificity, F1, confusion matrix를 산출한다.
- top-risk 5%, 10%, 20%에서 실제 산불 포착률을 평가한다.
- `Target_0A`, `Target_0B1`, `Target_0B2`를 분리해 평가한다.
- 모델 선택, threshold 결정, 최종 test 평가를 분리한다.
- lockbox test는 최종 후보가 확정된 후 한 번만 사용한다.

### 3.2 변경할 점

- 기존 모델, 튜닝 결과, 앙상블 가중치와 threshold를 재사용하지 않는다.
- `F1_score`~`F5_score` 요인점수는 사용하지 않는다.
- 수정된 캐나다지수와 새 최종 데이터만 사용한다.
- 기존 lockbox는 이미 이전 머신러닝에서 결과를 확인했으므로 새 최종 검증셋으로 재사용하지 않는다.
- 새 strict lockbox와 CV manifest를 모델 실행 전에 다시 만들고 고정한다.
- threshold 성능은 가능한 한 nested 방식으로 평가해 threshold 선택 편향을 줄인다.
- recall 중심 과제이므로 기존 F1 외에 recall에 더 큰 가중치를 주는 `F2-score`를 추가한다.

## 4. 데이터 및 변수 사용 원칙

### 4.1 목적변수

- `Target=1`: 실제 산불 발생
- `Target=0`: 비발생 대조 표본

전체 데이터는 17,045행이며 Target 1은 1,553행이다.

### 4.2 X에서 반드시 제외할 변수

다음 변수는 결과 또는 표본 생성방식을 직접 나타내거나 식별·분할용이므로 모델 입력 X에서 제외한다.

| 구분 | 변수 |
| --- | --- |
| 목적변수 | `Target` |
| 누수 위험 | `샘플유형`, `실험안`, `시간샘플링방식`, `공간층` |
| 추적·식별 | `샘플ID`, `기준시각`, `기상셀ID` |
| 사건 연결 | `fire_id`, `원본_fire_id`, `후보점ID`, `source_fire_id` |
| 분할 전용 | `모델링_그룹ID` |
| 캐나다지수 검증 | `캐나다지수_기준날짜`, `캐나다지수_정책` |
| 위치 원값 | `위도`, `경도` |

`샘플가중치`는 X에 넣지 않고 모델의 `sample_weight` 인자로만 사용한다.

### 4.3 중복 표현 정리

같은 정보를 여러 형태로 동시에 넣어 불필요한 중복과 중요도 분산이 발생하지 않도록 한다.

- 월: `월_key` 대신 `월_sin`, `월_cos`
- 시간: `시간_key` 대신 `시간_sin`, `시간_cos`
- 풍향: `시점_풍향_deg` 대신 `풍향_sin`, `풍향_cos`
- 거리: 원본 거리 변수보다 `log1p` 거리 변수를 기본 사용
- 토지피복: 코드와 명칭을 동시에 사용하지 않고 명칭 중심으로 구성
- `FFMC_논문식_발생확률`은 `Indexed_FFMC`의 결정적 변환이므로 둘을 동시에 주 모델에 넣지 않는다.

### 4.4 임상도 변수

임상도는 17,045행 중 28행만 실제 매칭되어 있다. 주 모델에서는 제외하고 최종 단계의 민감도 실험에서만 사용한다.

임상도 미매칭을 0 또는 “미상”으로 채운 변수를 주 모델에 넣으면 모델이 실질적인 산림 특성보다 매칭 여부를 학습할 가능성이 있다.

## 5. 피처셋 계획

피처셋의 큰 구분은 EDA 결과에 근거하지만, 모든 변수를 EDA에서 유의했던 변수만으로 제한하지는 않는다. EDA는 관찰된 차이와 후보 메커니즘을 제시하고, 머신러닝 단계에서는 그 신호가 strict CV의 실제 예측 성능으로 이어지는지 검증해야 한다.

따라서 피처셋은 다음 두 종류로 구분한다.

1. `EDA 핵심 피처셋`: 매칭 EDA에서 방향과 안정성이 비교적 명확했던 변수 중심
2. `전체 후보 피처셋`: EDA상 약하거나 권역별로 달랐던 변수까지 포함해 추가 예측정보가 있는지 확인

변수 선택의 최종 근거는 EDA의 p-value나 SHAP 중요도 하나가 아니라 동일 split에서 수행한 OOF AUPRC, recall 70% 운영점, Target 0A 성능과 fold 안정성이다.

### 5.1 날씨 피처셋의 EDA 근거

`jsw/final_eda.md`에서 직전 24~48시간 최소·평균습도와 D-1 최소습도가 가장 안정적인 기상 신호로 확인됐다. 직전 24~48시간 및 D-1 강수 결핍도 같은 방향을 보였다.

풍속은 강원도 전체 평균에서는 습도보다 효과가 약했지만 영동 해안형에서 상대적으로 강했다. 기온과 기압은 매칭 후 독립적인 차이가 약해 핵심 신호보다는 계절·권역 및 종관 배경을 보정하는 보조 후보로 본다.

이에 따라 날씨 변수는 다음처럼 구분한다.

- 핵심: 직전 24·48시간 습도, D-1~D-3 습도, 직전 24·48시간 강수량, D-1 강수량
- 권역별 핵심·전체 보조: 시점 및 직전 풍속, 풍향, 서풍계열 여부
- 보조: 기온, 기압, 기압변동
- 층화·상호작용 기준: 기후지형유형, 월·시간 주기

EDA에서 강했던 `rh_local_q05`와 무강수 지속시간 변수는 현재 최종 학습데이터에 포함되어 있지 않다. 향후 추가할 경우 각 표본 기준시각 이전 자료만 사용하는 누수 없는 생성 규칙을 먼저 확정하고, 현재 모델과 별도의 파생변수 민감도 실험으로 평가한다.

### 5.2 공간·토지피복 피처셋의 EDA 근거

`jsw/final_eda.md`의 공간 대조군 분석에서는 도로 최단거리의 차이가 가장 강했고, 시가화 및 산림 최단거리도 큰 차이를 보였다. 산불 지점은 같은 공간층 안에서도 저고도·완경사·하부 사면에 치우쳤으며 생활권-WUI와 비산림 접경 피복에 집중됐다.

이에 따라 공간 변수는 다음처럼 구분한다.

- 핵심: 도로·시가화·산림 최단거리, 고도, 경사도, TPI
- 핵심 토지피복: 산림·시가화건조지역·농업지역·초지·나지·도로 및 비산림 WUI 접경후보
- 보조: 농업·임도·등산로 최단거리와 사면방향
- 민감도 전용: 매칭률이 매우 낮은 임상도 변수

도로·시가화 접근성과 토지피복은 발화 원인을 직접 나타내는 변수가 아니라 관찰된 공간적 위치와 접근성의 프록시로 해석한다.

### 5.3 캐나다 산불지수 피처셋의 EDA 근거

`jsw/캐나다산불지수_eda.md`의 동일 기상셀·연도·월·시간대 매칭 분석에서는 `FFMC`가 가장 안정적인 지수였고, `ISI`와 `FWI`가 약하지만 일관된 양의 보조 신호로 남았다. `DMC`, `DC`, `BUI`는 전체 단순 비교에서는 차이가 있었지만 매칭 후 전체 단위의 강건성이 약해졌다. `FFMC_10일평균`과 `Indexed_FFMC`도 발생 순간의 독립적인 신호는 약했다.

따라서 캐나다지수 전체를 한꺼번에 주 피처셋으로 확정하지 않고 다음 후보군을 사전에 구분한다. 주 모델의 완전 교차 실험에서는 `CANADA_NONE`을 포함한 4개 선택지를 사용한다.

| 캐나다지수 후보군 | 구성 | 목적 |
| --- | --- | --- |
| `CANADA_NONE` | 캐나다지수 미사용 | 캐나다지수 추가효과를 비교하기 위한 기준 |
| `CANADA_CORE_EDA` | FFMC, ISI, FWI | 매칭 EDA에서 안정적으로 남은 단기 지수 |
| `CANADA_LONG_TERM_SENSITIVITY` | DMC, DC, BUI | 장기 건조지수의 추가 예측정보 확인 |
| `CANADA_ALL_CONTINUOUS` | FFMC, FFMC 10일 평균, DMC, DC, ISI, BUI, FWI | 연속형 캐나다지수 전체 기준 실험 |

`INDEXED_FFMC_REFERENCE`는 위 4개와 완전 교차하는 주 후보군이 아니다. `Indexed_FFMC` 단독 로지스틱 모델로 한 번 구성하여 강원도 선행연구 재현 기준선으로 별도 평가한다.

`Indexed_FFMC`와 `FFMC_논문식_발생확률`은 결정적으로 연결된 변환값이므로 동시에 사용하지 않는다. `FFMC_논문식_발생확률`은 주 모델 변수가 아니라 선행연구 참고값으로만 취급한다.

주 피처셋은 임의로 일부 조합만 고르는 방식이 아니라 다음 세 축을 완전 교차하여 구성한다.

| 11 | `WS_ALL__CANADA_LONG__LC_NONE` | 전체 날씨·공간 + DMC·DC·BUI |
| 12 | `WS_ALL__CANADA_ALL__LC_NONE` | 전체 날씨·공간 + 연속형 캐나다지수 7개 |
| 13 | `WS_ALL__CANADA_NONE__LC_USED` | 전체 날씨·공간 + 토지피복 |
| 14 | `WS_ALL__CANADA_CORE__LC_USED` | 전체 날씨·공간 + FFMC·ISI·FWI + 토지피복 |
| 15 | `WS_ALL__CANADA_LONG__LC_USED` | 전체 날씨·공간 + DMC·DC·BUI + 토지피복 |
| 16 | `WS_ALL__CANADA_ALL__LC_USED` | 전체 날씨·공간 + 연속형 캐나다지수 7개 + 토지피복 |

여기에 주 모델과 완전 교차하지 않는 `INDEXED_FFMC_REFERENCE` 단독 로지스틱 기준선 1개를 별도로 추가한다. 따라서 비교표에는 주 피처셋 16개와 선행연구 기준선 1개가 존재한다.

- 하나의 일반 모델 알고리즘: 주 피처셋 16개
- 5-fold 기준 기본 학습: `16 × 5 = 80회`
- 후보 알고리즘이 `K`개일 때: `16 × K`개 모델·피처셋 조합
- 전체 기본 학습 횟수: `16 × K × 5`
- 선행연구 재현 기준선: 별도 1개 조합, 5-fold 학습 5회

class weight, 하이퍼파라미터 trial과 calibration은 위 피처셋 경우의 수와 별도의 모델 설정 축이다. Stage 1에서 모든 설정을 완전 교차하지 않고 기본 설정과 사전에 정한 불균형 처리 설정만 비교한다.

주 모델 screening은 16개 피처셋을 동일 split과 동일 평가 기준으로 비교한다. EDA 핵심 모델과 전체 모델의 성능이 사실상 같으면 변수 수가 적고 설명이 쉬운 EDA 핵심 모델을 우선한다.

토지피복은 두 표현을 별도로 비교할 수 있다.

1. 범주형 중심: `토지피복_L1_NAME`, `토지피복_L2_NAME`, `토지피복_산림유형`
2. 이진 flag 중심: 산림지역, 시가화건조지역, 농업지역, 초지, 나지, 도로, 활엽수림, 침엽수림, 혼효림

두 표현을 모두 한 세트에 중복 투입하지 않고 CV 결과로 선택한다.

### 5.5 피처셋 선택과 SHAP의 역할

피처셋은 SHAP 결과를 본 뒤 처음 만드는 것이 아니라 위 EDA와 변수 구조에 따라 모델 학습 전에 16개로 정의한다. 먼저 동일한 CV에서 완전 교차 피처셋과 ablation을 비교한 뒤, 개발용 OOF SHAP으로 모델이 어떤 변수를 어떤 방향으로 사용했는지 점검한다.

SHAP 중요도가 낮다는 이유만으로 변수를 즉시 제거하지 않는다. 상관된 변수는 기여도를 나누어 가질 수 있고, 개별 중요도가 낮아도 다른 변수와 결합해 성능에 기여할 수 있기 때문이다. SHAP에서 이상하거나 지속적으로 기여가 낮은 변수가 발견되면 제한된 축소 피처셋만 추가하고, 제거 여부는 반드시 제거 전후 OOF 성능과 fold 안정성으로 결정한다.

최종 피처셋, 모델, calibration과 threshold가 고정된 후에는 lockbox SHAP을 보고 다시 변수를 변경하지 않는다.

## 6. 데이터 분할 계획

### 6.1 Lockbox의 의미와 출처

Lockbox는 원래 학습데이터에 포함된 별도 데이터가 아니다. 이전 로지스틱 분석의 `_build_logistic_notebook.py`에서 모델 선택 이후의 최종 성능을 확인하기 위해 전체 데이터 일부를 별도로 분리하면서 도입한 최종 테스트셋이다.

일반적인 5-fold CV와 역할이 다르다.

| 구분 | 사용 시점 | 역할 | 결과를 보고 모델 변경 |
| --- | --- | --- | --- |
| inner CV | 학습·튜닝 중 | 하이퍼파라미터, class weight, threshold 선택 | 가능 |
| outer 5-fold CV | 모델 비교 중 | development OOF 일반화 성능 평가 | 가능 |
| lockbox test | 모든 선택 완료 후 | 최종 고정 후보의 마지막 성능 확인 | 금지 |

5-fold CV만으로도 모델 평가는 가능하므로 lockbox가 모든 머신러닝 작업의 필수 요소는 아니다. 그러나 이번 분석처럼 피처셋, 모델, class weight, threshold, calibration, 앙상블을 반복 비교하면 연구자가 outer CV 결과에 점차 맞춰 의사결정을 하게 된다. 이런 반복 선택에 대한 최종 확인 장치로 lockbox를 유지한다.

즉 이번 계획에서 lockbox는 학습 성능을 높이기 위한 데이터가 아니라, 반복 튜닝으로 인해 development CV 성능이 낙관적으로 변했는지 확인하기 위한 봉인된 시험지다.

### 6.2 기존 lockbox를 재사용하지 않는 이유

기존 `machine_learning` 작업에서는 기존 lockbox 결과를 이미 확인했다. 해당 데이터는 더 이상 완전히 보지 않은 최종 검증셋이 아니다.

새 모델링에서는 모델을 학습하기 전에 새로운 split manifest를 생성하고 이후 변경하지 않는다.

### 6.3 새 lockbox 생성 원칙

새 lockbox는 완전한 행 단위 무작위 추출로 만들지 않는다. 다음 조건을 만족하도록 전체의 약 20%를 그룹 단위로 분리한다.

- 전체 Target 1/0 비율과 유사
- `Target_1`, `Target_0A`, `Target_0B1`, `Target_0B2` 구성비와 유사
- 기후지형유형 분포와 가능한 한 유사
- 동일 사건과 연결된 양성·대조 표본을 서로 분리하지 않음
- 동일 기상셀·기준시각 노출을 서로 분리하지 않음
- 동일 strict 날짜 성분을 서로 분리하지 않음

따라서 lockbox는 “완전 랜덤 표본”이 아니라 전체 설계 비율을 최대한 유지하면서 관련 표본을 함께 이동시키는 `group-stratified holdout`이다.

Lockbox를 만든 다음에는 다음 정보를 확인한다.

- 전체 및 lockbox 행 수
- Target 1 수와 양성률
- 샘플유형별 행 수와 비율
- 기후지형유형별 행 수와 비율
- development와 lockbox 사이 그룹·기상노출·날짜 overlap 0건

### 6.4 누수 방지 그룹

다음 관계 중 하나라도 공유하는 표본은 같은 연결 성분으로 묶어 서로 다른 fold에 들어가지 않게 한다.

- 동일 `모델링_그룹ID`
- 동일 기상 노출: `기상셀ID × 기준시각`
- 동일 strict 날짜
  - Target 1과 연결된 0-A는 원 산불 발생 날짜
  - 0-B1·0-B2는 실제 기준 날짜

그룹명은 `date_exposure_component_group`으로 정의한다.

각 split에서 다음 누수 건수가 모두 0인지 검증한다.

- 모델링 그룹 overlap
- 기상 노출 overlap
- strict 날짜 overlap
- Target 1 실제 발생일 overlap

### 6.5 split 구조

| 구분 | 비율·fold | 용도 |
| --- | --- | --- |
| 새 lockbox test | 약 20% | 최종 후보 최초 1회 평가 |
| development | 약 80% | 모델 선택과 threshold 결정 |
| outer CV | development 5-fold | 정직한 OOF 성능 평가 |
| inner CV | 각 outer-train 4-fold | 하이퍼파라미터·class weight·threshold 선택 |

연결 성분 크기가 불균형할 수 있으므로 단순 무작위 분할 대신 행 수, Target 1 수, 샘플유형, 기후지형유형을 최대한 맞추는 deterministic greedy group assignment를 사용한다.

Lockbox는 모델 학습, 피처 선택, 튜닝, calibration 방법 선택, threshold 산출에 사용하지 않는다. 최종 평가 결과가 기대보다 낮더라도 같은 lockbox를 보고 다시 모델을 수정하지 않는다. 추가 수정이 필요하면 해당 결과는 최종 test가 아니라 분석 피드백이 되며, 진정한 최종 성능은 이후 확보되는 새로운 외부 데이터로 다시 평가해야 한다.

### 6.6 연도 분할

현재 데이터는 2020년 8,351행, 2021년 8,694행이지만 1,530개 모델링 그룹, 9,155행이 두 연도에 걸쳐 있다. 따라서 단순 `2020 학습 → 2021 테스트`는 연결된 양성·대조군을 분리해 그룹 누수를 만들 수 있다.

연도 분할은 주 split으로 사용하지 않고 다음 용도로만 사용한다.

- 최종 후보의 연도별 성능 보고
- 2020/2021 성능 편차 확인
- 향후 완전히 새로운 연도 데이터가 확보됐을 때 외부검증 설계 참고

## 8. 클래스 불균형 처리

Target 1 비율은 약 9.1%다. 다음 방법을 비교한다.

- 기본 가중치 없음
- `class_weight="balanced"` 또는 모델별 동등 옵션
- `scale_pos_weight`
- 기존 `샘플가중치` 적용

SMOTE는 기본 계획에서 사용하지 않는다. 시간·공간·기상 조합을 인위적으로 합성하면 실제 존재하지 않는 산불 환경 표본이 만들어질 수 있기 때문이다.

class weight를 사용하면 순위 성능은 좋아질 수 있지만 출력 확률이 실제 발생확률과 달라질 수 있다. 최종 확률 해석 전에는 calibration을 별도로 수행한다.

## 9. 평가 지표와 사용 목적

평가지표는 하나로 합치지 않고 역할별로 분리한다.

### 9.1 모델 판별력 및 순위 선택

| 지표 | 우선순위 | 사용 목적 |
| --- | ---: | --- |
| `AUPRC` | 1 | 불균형 데이터에서 산불 표본을 상위 위험도로 정렬하는 성능 |
| `Target_1 vs Target_0A AUPRC` | 2 | 같은 위치·유사 시간 조건의 어려운 비발생 표본 구분 |
| `AUROC` | 보조 | 전체 양성과 음성의 순위 분리 |
| fold별 AUPRC 평균·표준편차 | 필수 | 특정 fold에만 성능이 몰리는지 확인 |
| group bootstrap 95% CI | 필수 | 성능 불확실성 확인 |

AUPRC를 주지표로 사용하는 이유는 비발생 표본이 많은 상황에서 AUROC와 Accuracy가 높게 보일 수 있기 때문이다.

Accuracy는 결과표에 참고용으로 남길 수 있지만 모델 선택 기준으로 사용하지 않는다.

### 9.2 Recall 중심 threshold 평가

기본 운영점은 `recall_ge_0.70`이다. 추가로 `recall_ge_0.90`을 고회수 운영점으로 제공한다.

| 운영점 | 역할 |
| --- | --- |
| `fixed_0.50` | 일반적인 0.5 기준이 왜 부적절할 수 있는지 확인하는 진단값 |
| `best_f1` | 기존 분석과 비교하기 위한 참고값 |
| `best_f2` | recall에 더 큰 가중치를 둔 균형점 |
| `recall_ge_0.70` | 기본 운영 후보 |
| `recall_ge_0.90` | 산불 누락을 더 줄이는 고회수 후보 |
| `recall_ge_0.95` | 경보 부담을 확인하는 스트레스 테스트 |

각 threshold에서 다음 지표를 모두 산출한다.

- `threshold`
- `TP`, `FP`, `FN`, `TN`
- `recall`
- `precision`
- `specificity`
- `false_positive_rate`
- `F1`
- `F2`
- `balanced_accuracy`
- `MCC`
- `selected_n`
- `selected_rate`
- `FP_per_TP`

보고서에서는 recall 비율뿐 아니라 놓친 실제 산불 수인 `FN`을 반드시 함께 표시한다.

`F2-score`는 recall에 precision보다 더 큰 가중치를 두므로 recall 중심 후보 비교에 사용한다. 다만 F2 하나로 최종 모델을 정하지 않고 recall, precision, FN, selected rate를 함께 본다.

### 9.3 Recall 목표 threshold 선택 규칙

`recall_ge_0.70` threshold는 다음 규칙으로 선택한다.

1. validation 예측에서 recall 0.70 이상을 만족하는 threshold 후보를 찾는다.
2. 그중 precision이 가장 높은 threshold를 선택한다.
3. precision이 같으면 `selected_rate`가 더 낮은 threshold를 선택한다.
4. 그래도 같으면 더 높은 threshold를 선택한다.

`recall_ge_0.90`, `recall_ge_0.95`도 같은 규칙을 사용한다.

이 방식은 “recall 목표를 달성하면서 불필요한 경보를 최대한 줄이는 threshold”를 찾는 방법이다.

### 9.4 Top-risk capture

현장 점검 가능 수량이 고정된 경우 threshold보다 상위 위험도 비율이 더 직접적일 수 있다.

다음 구간을 평가한다.

- top 5%
- top 10%
- top 20%
- top 30%

각 구간에서 다음 값을 산출한다.

- 선택 표본 수
- 전체 선택 비율
- 실제 산불 포착 수
- 전체 산불 중 포착 비율
- precision
- 기본 발생률 대비 lift

### 9.5 확률 품질

| 지표 | 목적 |
| --- | --- |
| `Brier score` | 예측확률과 실제 결과의 평균 제곱오차 |
| `Log loss` | 확신한 오답에 큰 페널티 부여 |
| calibration curve | 예측확률과 실제 발생비율 비교 |
| calibration intercept·slope | 과대·과소 예측 및 확률 기울기 확인 |

샘플링된 데이터의 Target 1 비율 9.1%는 실제 운영 발생률이 아니다. 따라서 모델 점수를 곧바로 실제 산불 발생확률이라고 표현하지 않는다.

최종 결과는 기본적으로 `산불위험 점수`로 표현하고, 실제 운영 모집단 발생률이 확보된 후 별도 확률 보정을 검토한다.

### 9.6 Subgroup 평가

전체 성능 외에 다음 subgroup을 별도로 평가한다.

- `Target_1 vs Target_0A`
- `Target_1 vs Target_0B1`
- `Target_1 vs Target_0B2`
- 기후지형유형
- 2020년 / 2021년
- 12시 이전 / 12시 이후
- 토지피복 유형

특히 `Target_0A`를 가장 중요한 hard-negative로 본다. 0-B2 성능만 높은 모델은 쉬운 시간·공간 배경을 구분한 것일 수 있으므로 최종 후보로 바로 선택하지 않는다.

## 10. Threshold를 정직하게 평가하는 방법

threshold를 평가 데이터의 정답을 보고 다시 정하면 성능이 과대평가된다. 다음 순서를 지킨다.

### 10.1 OOF 예측의 의미와 용도

`OOF(Out-Of-Fold) 예측`은 각 표본을 학습에 사용하지 않은 fold 모델로 생성한 예측값이다. 5-fold CV에서는 데이터를 5개 fold로 나눈 뒤, 매번 4개 fold로 모델을 학습하고 제외된 1개 fold를 예측한다. 이 과정을 5번 반복하여 development의 모든 표본에 대해 학습 외 예측확률을 하나씩 만든다.

일반적인 학습 데이터 재예측값은 해당 표본을 이미 본 모델의 결과이므로 성능이 과대평가될 수 있다. 모델 비교, ROC·PR curve 작성, AUROC·AUPRC 계산 및 최종 threshold 결정에는 학습 데이터 재예측값이 아니라 OOF 예측값을 사용한다.

development OOF 예측 결과는 모델별 CSV로 저장하며 최소한 다음 열을 포함한다.

| 열 | 설명 |
| --- | --- |
| `sample_id` | 원본 표본 식별자 |
| `split` | `development_oof` 또는 `lockbox` 구분 |
| `fold` | 해당 표본이 검증에 사용된 outer fold 번호 |
| `y_true` | 실제 산불 발생 여부 |
| `y_prob` | 산불 발생 예측확률 또는 고위험 점수 |
| `model_name` | 모델명 |
| `feature_set` | 사용 피처셋 |
| `group_id` | 동일 사건·대조군 또는 누수 방지 그룹 식별자 |

예측확률은 임의로 반올림하지 않고 원래 정밀도로 저장한다. 이 CSV가 있으면 모델을 다시 학습하지 않아도 ROC curve, PR curve, AUROC, AUPRC, Brier score, threshold별 confusion matrix·recall·precision·specificity·F1·F2·selected rate를 재현할 수 있다.

AUROC와 AUPRC는 모든 threshold에 걸친 순위 성능이므로 특정 threshold를 바꾼다고 값이 달라지는 지표가 아니다. 반면 recall, precision, specificity, F1, F2와 confusion matrix는 적용한 threshold에 따라 달라진다.

OOF와 lockbox의 역할은 구분한다.

- `development OOF`: 모델 비교, calibration 선택 및 threshold 결정에 사용하는 개발 검증 결과
- `lockbox`: 모델, calibration 및 threshold를 모두 고정한 후 최종 성능을 한 번 확인하는 결과

### 10.2 Outer fold 평가

각 outer fold에서:

1. outer-train만 사용해 inner OOF 예측을 만든다.
2. inner OOF에서 recall 70%, 90%, 95% threshold를 정한다.
3. outer-train 전체로 모델을 재학습한다.
4. 고정한 threshold를 outer-validation에 적용한다.
5. outer-validation의 실제 recall, precision, selected rate를 저장한다.

이 결과가 개발 단계의 정직한 threshold 일반화 성능이다.

### 10.3 최종 threshold 고정

최종 모델과 피처셋이 선택된 후 development 전체 OOF에서 최종 threshold를 한 번 결정한다.

그 다음:

1. 최종 모델을 development 전체로 재학습한다.
2. 새 lockbox에 확률 또는 위험점수를 생성한다.
3. development에서 정한 threshold를 그대로 적용한다.
4. lockbox recall이 정확히 70%가 아니더라도 다시 조정하지 않는다.

`recall_ge_0.70`은 development에서 정한 목표 운영점이며, lockbox에서는 실제 달성 recall을 그대로 보고한다.

## 11. 모델 선택 규칙

recall만으로 모델을 선택하면 모두 1로 예측하는 모델이 이긴다. 다음 계층형 규칙으로 최종 후보를 선택한다.

### 11.1 필수 통과 조건

- split 누수 검증 0건
- OOF 예측 누락·중복 0건
- score NaN/inf 0건
- 모든 outer fold에 Target 1 존재
- `recall_ge_0.70` 운영점 산출 가능

### 11.2 1차 순위

1. strict development OOF AUPRC
2. `Target_0A` AUPRC
3. fold별 AUPRC 안정성 및 95% CI

### 11.3 Recall 중심 최종 선택

AUPRC 최고 모델과 차이가 `0.005` 이내인 후보들을 대상으로 다음 순서로 선택한다.

1. honest outer-CV `recall_ge_0.70`의 precision
2. `recall_ge_0.70`의 selected rate
3. fold별 recall 최솟값
4. `recall_ge_0.90` 운영 가능성
5. top 10%, 20% capture
6. Brier score와 log loss

즉 최종 모델은 단순히 AUPRC가 가장 높은 모델이 아니라, 충분한 순위 성능을 가진 후보 중 recall 70%를 가장 적은 경보로 달성하는 모델이다.

## 12. 학습 단계

### Stage 0. 데이터·분할 감사

- 최종 CSV 무결성 재검증
- 모델 제외 변수 목록 확정
- 새 strict component group 생성
- 새 lockbox, outer, inner manifest 생성 및 고정
- fold별 행 수, Target 1, 샘플유형, 기후지형유형 분포 확인
- 모든 누수 audit 0 확인

### Stage 1. 넓은 기본 모델 screening

- 완전 교차로 사전 정의한 주 피처셋 16개 × 모든 후보 모델 실행
- `INDEXED_FFMC_REFERENCE`는 별도 로지스틱 기준선으로 실행
- 기본 설정과 class-weight 설정 비교
- strict OOF AUPRC, subgroup, threshold, top-risk 산출
- 전체 조합표를 top-N으로 자르지 않고 저장

### Stage 2. 집중 튜닝

- Stage 1 상위 3~5개 후보만 Optuna 튜닝
- objective는 inner CV AUPRC
- recall 70% precision과 0A 성능을 보조 objective로 저장
- outer fold validation은 튜닝에 사용하지 않음

### Stage 3. 피처 ablation

최종 후보 모델에서 다음을 제거하며 성능 변화를 확인한다.

- 캐나다지수 제거
- 토지피복 제거
- 기상변수 제거
- 지형·거리 제거
- 계절·시간 제거

캐나다지수는 지수 간 중복이 크므로 다음도 비교한다.

- FWI 단독
- FFMC + FWI
- `CANADA_CORE_EDA`: FFMC + ISI + FWI
- `CANADA_LONG_TERM_SENSITIVITY`: DMC + DC + BUI
- `CANADA_ALL_CONTINUOUS`: 전체 연속형 캐나다지수 7개
- 전체 7개에서 지수를 하나씩 제거하는 leave-one-index-out

이 단계에서 개발용 OOF SHAP을 함께 산출해 EDA 방향과 모델 사용 방향, fold별 중요도 안정성, 상관된 변수 사이의 중요도 분산을 점검한다. SHAP 결과에 따라 무제한으로 변수를 제거하지 않고, 사전에 정한 ablation 및 최대 1~3개의 추가 축소 실험만 허용한다. 추가 축소 모델도 동일한 nested CV로 다시 평가한다.

### Stage 4. 앙상블

Step 4는 development OOF만 사용하며 lockbox에 접근하지 않는다. 단일 모델 성능이 충분하면 단일 모델을 우선하고, 아래 채택 기준을 통과한 앙상블만 Step 5로 넘긴다.

#### 입력 base stream

| stream | 출처 | 역할 |
| --- | --- | --- |
| tuned LightGBM baseline | Step 2 | 단일 1위 기준 |
| tuned LightGBM `CANADA_DROP_ISI` | Step 3 | 대체 민감도 후보 |
| Step 1 기본 RandomForest | Step 1 | bagging 대표 |
| Step 1 기본 ExtraTrees | Step 1 | 다양성 대표 |
| tuned XGBoost | Step 2 | 확률 품질 보조 |
| tuned HGB | Step 2 | 높은 recall 진단용 고정 조합 |

LightGBM baseline과 `CANADA_DROP_ISI`는 같은 조합에 동시에 넣지 않는다. CatBoost와 tuned RandomForest 2개는 fold 불안정성 또는 중복성 때문에 제외한다.

#### 고정 조합

- `LGBM + RF`: 산술평균, 기하평균
- `LGBM + RF + ET`: 산술평균, 기하평균, rank 평균, 최대값
- `LGBM + RF + XGB`: 산술평균, 기하평균, rank 평균, 최대값
- `LGBM + RF + ET + XGB`: 산술평균, 기하평균
- `LGBM + RF + HGB`: 산술평균, 기하평균, 최대값
- 위 조합을 LightGBM baseline 버전과 `CANADA_DROP_ISI` 버전으로 각각 비교한다.

rank 평균은 ranking 전용이고 최대값은 recall 진단용이다. 최종 probability score 후보는 산술평균, 기하평균, nested weighted ensemble, nested stacking으로 제한한다.

#### Nested weight와 stacking

가중치와 stacking을 현재 outer OOF 전체에 직접 fit하지 않는다. 각 outer-train 안에서 Step 2와 동일한 `StratifiedGroupKFold(4, shuffle=True, random_state=20260622+1000+outer_fold)` inner OOF를 새로 생성한다.

- inner base stream: LightGBM baseline, LightGBM `DROP_ISI`, Step 1 RF, Step 1 ET, tuned XGBoost
- 예상 base fit: `5 streams × 5 outer × 4 inner = 100 fits`
- LightGBM과 XGBoost: 해당 outer fold의 Step 2 best parameter 재사용
- RF와 ET: Step 1 고정 preset 재사용
- inner 및 outer train-validation 그룹 교집합은 0이어야 한다.

Optuna weight search는 `LGBM+RF+ET`, `LGBM+RF+XGB`, `LGBM+RF+ET+XGB`에 대해 weighted mean과 weighted geometric mean을 비교한다. outer fold별 300 trials, 비음수 weight, 합계 1로 제한한다. inner OOF AUPRC를 우선하고 `0.0005` 이내 후보는 Target_0A AUPRC, top 10% capture, Brier, 최대 단일 weight 순으로 선택한다.

stacking은 같은 inner base OOF를 재사용한다. `LGBM+RF+ET`, `LGBM+RF+XGB`에 대해 `StandardScaler + L2 LogisticRegression(C=1)`을 적용하고 raw probability 입력과 clipped-logit 입력을 각각 outer-validation에서 평가한다.

#### 채택 기준

- best single보다 AUPRC가 `0.002` 이상 개선되거나, 작은 AUPRC 개선과 함께 recall 70% selected rate 또는 top 10% capture가 `0.5%p` 이상 개선
- 5개 fold 중 3개 이상 개선, 최악 fold ΔAUPRC가 `-0.01` 이상
- Target_0A AUPRC 하락이 `0.002` 이내
- Brier와 log loss가 best single보다 5% 이상 악화되지 않음
- weighted ensemble이 3개 이상 fold에서 단일 weight `0.95` 이상이면 단일 모델 붕괴로 보고 제외
- `DROP_ISI` 조합은 대응 baseline 조합보다 전체 AUPRC가 높고 3개 이상 fold에서 개선될 때만 채택

성능 차이가 `0.001` 미만이고 운영점도 유사하면 고정식과 적은 base 모델을 우선한다. 통과 후보가 없으면 Step 2 baseline LightGBM을 유지한다. 최종 후보는 group 단위 paired bootstrap 1,000회와 threshold·top-risk·subgroup 지표를 함께 보고 확정한다.

Step 4에서는 calibration을 수행하지 않는다. 선택된 raw probability score만 Step 5로 넘기며, 앙상블 선택에도 lockbox를 사용하지 않는다.

### Stage 5. Calibration 및 최종 threshold

- 상위 1~3개 후보에 sigmoid와 isotonic 적용
- ranking 성능과 확률 품질 분리 평가
- probability score 최종 후보 결정
- development OOF에서 recall 70%, 90%, 95% threshold 고정
- 최종 후보 manifest와 모델 artifact 저장

### Stage 6. 새 lockbox 최초 평가

- 후보, 피처셋, calibration, threshold를 모두 고정한 후 실행
- lockbox로 후보 재선택·재튜닝 금지
- AUPRC, subgroup, threshold, top-risk, calibration 결과 산출
- development OOF 대비 성능 변화 보고

### Stage 7. 최종 모델 해석

- SHAP 또는 permutation importance
- 전체 중요도와 기후지형유형별 중요도
- FN 사례 분석
- recall 70%에서 FP가 많이 발생하는 대조군 분석
- top-risk 구간의 변수 분포 분석

SHAP 중요도는 인과효과가 아니라 모델 예측 기여도로 해석한다.

### Stage 8. 최종 보고서

- 데이터 및 누수 수정

- 피처셋 비교

## 15. 최종 보고 방식

최종 결과를 “산불을 정확히 맞히는 분류기”라고 표현하지 않는다.

다음 형태로 보고한다.

> 모델은 각 위치·시각의 산불위험 점수를 산출한다. 기본 threshold는 development에서 recall 70%를 목표로 정했으며, 이 운영점에서 실제 산불 포착률, 놓친 산불 수, 경보 대상 비율과 precision을 함께 제시한다. 더 높은 안전성이 필요하면 recall 90% 운영점을 사용할 수 있지만 경보 대상과 오경보가 증가한다.

핵심 결과는 반드시 다음 세 문장으로 요약할 수 있어야 한다.

1. 실제 산불을 몇 건 중 몇 건 포착했는가?
2. 그 포착률을 위해 전체 위치의 몇 %를 경보 대상으로 지정했는가?
3. 경보 대상 중 실제 산불 비율은 얼마인가?

이 세 값이 산불 누락 최소화와 현장 점검 부담 사이의 실제 trade-off를 나타낸다.
