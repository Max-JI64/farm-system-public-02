각 단계에서는 다음 원칙을 지킨다.

- 모델을 한 종류씩 실행하고 결과를 별도 파일로 저장한다.
- development 데이터의 outer OOF 예측으로 모델과 피처셋을 비교한다.
- threshold는 outer-validation 정답을 직접 보고 정하지 않고 inner OOF에서 정한다.
- lockbox는 최종 모델·피처셋·calibration·threshold가 확정되기 전까지 사용하지 않는다.
- 실행 전 계획과 실행 후 결과를 구분하여 기록한다.

## STEP 1. 여러 단일 모델 피처셋 screening

### STEP 1 상태

- 작성일: 2026-06-22
- 상태: 실행 전 계획
- 목적: 앙상블 전에 여러 머신러닝 모델을 각각 독립적으로 학습하고 모델·피처셋 조합별 성능을 비교
- 모델 단위: 각 알고리즘을 서로 결합하지 않은 단일 모델

Step 1에서 실행할 단일 머신러닝 모델은 다음 6개다.

| model_name | 역할 |
| --- | --- |
| `HistGradientBoosting` | sklearn 기반 비선형 boosting 기준 |
| `LightGBM` | 빠른 boosting 및 불균형 처리 |
| `XGBoost` | 규제가 가능한 boosting 비교 |
| `CatBoost` | 범주형 변수가 포함된 데이터 비교 |
| `RandomForest` | bagging 계열 기준 |
| `ExtraTrees` | 무작위성이 큰 bagging 비교 |

여기서 `단일 모델`은 하나의 알고리즘만 실행한다는 뜻이 아니다. 위 6개 모델을 각각 따로 학습하며, 모델들의 예측값을 평균·가중평균·stacking 등으로 결합하지 않는다는 뜻이다. 단일 모델 결과가 확보된 뒤에만 후속 단계에서 앙상블의 추가효과를 비교한다.

Step 1에서는 각 모델의 기본 설정과 사전에 정한 불균형 처리 설정만 비교한다. 모든 피처셋을 동일한 기본 모델 조건에서 공정하게 screening하기 위해 하이퍼파라미터 튜닝은 하지 않는다.

하이퍼파라미터 튜닝은 Step 2에서 수행한다. Step 1에서 탈락한 전체 192개 조합을 모두 튜닝하지는 않되, 성능 상위 조합만 너무 좁게 튜닝하지도 않는다. Step 2는 `주 튜닝 후보`와 `모델별 구제 튜닝 후보`를 분리해 진행한다.

SHAP 기반 변수 제거, 모델 결합, calibration과 lockbox 평가도 Step 1에서는 수행하지 않는다.

### STEP 1-1. 입력 데이터와 분할

- 입력 데이터: `data/학습데이터/최종_머신러닝_학습데이터.csv`
- 목적변수: `Target`
- 개발 데이터: 모델·피처셋 비교와 OOF 예측 생성에 사용
- lockbox: Step 1에서 접근 및 평가 금지
- outer CV: strict group 5-fold
- inner CV: 각 outer-train 내부의 strict group 4-fold
- 분할 단위: 계획서에서 정의한 `date_exposure_component_group`

모든 피처셋과 불균형 설정은 동일한 split manifest를 사용한다. 조합마다 fold를 새로 만들지 않는다.

다음 변수는 모델 입력 `X`에서 제외한다.

- `Target`
- `샘플ID`, `기준시각`, `기상셀ID`
- `샘플유형`, `실험안`, `시간샘플링방식`, `공간층`
- `fire_id`, `원본_fire_id`, `후보점ID`, `source_fire_id`
- `모델링_그룹ID`
- `캐나다지수_기준날짜`, `캐나다지수_정책`
- `위도`, `경도`
- 그 밖에 변수사전에서 `X 제외`로 지정한 변수

`샘플유형`은 모델 입력에는 사용하지 않고 `Target_0A`, `Target_0B1`, `Target_0B2` subgroup 평가에만 사용한다.

### STEP 1-2. 비교할 피처셋

각 단일 모델에 다음 세 실험 축을 완전 교차한 동일한 16개 피처셋을 적용한다.

| 실험 축 | 선택지 | 개수 |
| --- | --- | ---: |
| 날씨·공간 | `WS_CORE`, `WS_ALL` | 2 |
| 캐나다지수 | `CANADA_NONE`, `CANADA_CORE`, `CANADA_LONG`, `CANADA_ALL` | 4 |
| 토지피복 | `LC_NONE`, `LC_USED` | 2 |

```text
2 × 4 × 2 = 16개 피처셋
```

피처셋 ID는 다음과 같다.

1. `WS_CORE__CANADA_NONE__LC_NONE`
2. `WS_CORE__CANADA_CORE__LC_NONE`
3. `WS_CORE__CANADA_LONG__LC_NONE`
4. `WS_CORE__CANADA_ALL__LC_NONE`
5. `WS_CORE__CANADA_NONE__LC_USED`
6. `WS_CORE__CANADA_CORE__LC_USED`
7. `WS_CORE__CANADA_LONG__LC_USED`
8. `WS_CORE__CANADA_ALL__LC_USED`
9. `WS_ALL__CANADA_NONE__LC_NONE`
10. `WS_ALL__CANADA_CORE__LC_NONE`
11. `WS_ALL__CANADA_LONG__LC_NONE`
12. `WS_ALL__CANADA_ALL__LC_NONE`
13. `WS_ALL__CANADA_NONE__LC_USED`
14. `WS_ALL__CANADA_CORE__LC_USED`
15. `WS_ALL__CANADA_LONG__LC_USED`
16. `WS_ALL__CANADA_ALL__LC_USED`

`INDEXED_FFMC_REFERENCE`는 6개 단일 머신러닝 모델의 16개 주 피처셋에 포함하지 않는다. 선행연구 재현용 단독 로지스틱 기준선으로 별도 실행한다.

### STEP 1-3. 불균형 처리 설정

Target 1 비율이 약 9.1%이므로 다음 두 설정을 비교한다.

| imbalance_option | 설정 |
| --- | --- |
| `none` | class weight 미적용 |
| `balanced` | `class_weight="balanced"` |

각 단일 모델의 비교 단위는 다음과 같다.

```text
16개 피처셋 × 2개 불균형 설정 = 32개 조합
```

6개 단일 모델 전체의 주 비교 조합은 다음과 같다.

```text
6개 모델 × 16개 피처셋 × 2개 불균형 설정 = 192개 조합
```

기존 `샘플가중치`를 적용하는 실험은 기본 class weight 결과를 확인한 뒤 별도 민감도 실험으로 진행한다. Step 1에서는 SMOTE를 사용하지 않는다.

### STEP 1-4. 전처리와 모델 설정

전처리는 각 outer-train 안에서만 학습하여 validation 정보가 들어오지 않도록 pipeline으로 구성한다.

- 수치형 변수: 숫자형 변환과 결측 처리
- 범주형 변수: 학습 fold에서만 범주 인코딩
- 월·시간·풍향: 계획서에서 정의한 sin·cos 변수 사용
- 거리 변수: 기본적으로 `log1p` 변수를 사용하고 원본과 중복 투입하지 않음
- 토지피복: 범주형 표현과 이진 flag를 동시에 중복 투입하지 않음
- 변수 선택과 전처리 fitting: 반드시 train fold 내부에서만 수행

각 모델의 하이퍼파라미터는 사전에 정한 기본 설정으로 고정한다. 이 단계에서는 모델·피처셋의 넓은 비교가 목적이므로 피처셋마다 서로 다른 튜닝 결과를 적용하지 않는다.

모델별 고정 설정과 random seed는 실행 스크립트와 각 모델의 `run_manifest.json`에 저장한다.

### STEP 1-5. 학습과 OOF 예측 생성

각 `모델 × 피처셋 × 불균형 설정` 조합에서 다음 순서로 실행한다.

1. outer 5-fold를 순회한다.
2. outer-train 데이터만 사용해 전처리와 모델을 학습한다.
3. 학습에 사용하지 않은 outer-validation의 산불위험 예측값을 생성한다.
4. 5개 fold의 예측값을 합쳐 development 전체 OOF 예측을 만든다.
5. 각 표본에 OOF 예측이 정확히 한 번 존재하는지 검사한다.

순위 성능용 outer 모델의 예정 학습 횟수는 다음과 같다.

```text
6개 모델 × 16개 피처셋 × 2개 불균형 설정 × outer 5-fold = 960회
```

정직한 threshold 평가를 위해 각 outer fold에서는 추가로 다음 절차를 수행한다.

1. outer-train을 inner 4-fold로 나눈다.
2. inner OOF 예측으로 threshold 후보를 정한다.
3. outer-train 전체로 모델을 다시 학습한다.
4. 미리 정한 threshold를 outer-validation에 적용한다.
5. outer-validation의 실제 recall, precision, FN과 selected rate를 기록한다.

inner OOF threshold 산출에는 `192 × outer 5 × inner 4 = 3,840회`의 추가 학습이 필요하다. outer 모델 960회를 합치면 Step 1의 예정 fit 횟수는 최대 4,800회다. 모델별 조기 실패나 지원하지 않는 불균형 옵션이 있을 수 있으므로 실행 로그에는 예정 횟수와 별도로 실제 성공·실패 fit 수와 소요시간을 기록한다.

### STEP 1-7. 계산할 평가지표

- AUPRC
- AUROC
- Brier score
- log loss
- fold별 AUPRC 평균·표준편차
- group bootstrap 95% CI

#### Threshold 운영점

- `fixed_0.50`
- `best_f1`
- `best_f2`
- `recall_ge_0.70`
- `recall_ge_0.90`

각 운영점에서 다음 값을 저장한다.

- threshold
- TP, FP, FN, TN
- recall, precision, specificity
- false positive rate
- F1, F2
- balanced accuracy, MCC
- selected_n, selected_rate
- FP per TP

#### Subgroup 평가

- `Target_1 vs Target_0A` AUPRC
- `Target_1 vs Target_0B1` AUPRC
- `Target_1 vs Target_0B2` AUPRC
- 기후지형유형별 AUPRC와 recall

#### Top-risk 평가

- 상위 5%, 10%, 20%, 30%
- 선택 표본 수
- 실제 산불 포착 수
- capture rate
- precision
- lift

### STEP 1-8. 결과 판단 규칙

Step 1에서는 단일 지표만으로 모델이나 피처셋을 탈락시키지 않는다.

필수 통과 조건은 다음과 같다.

- split 누수 0건
- OOF 예측 누락·중복 0건
- 예측값 NaN·inf 0건
- 모든 outer fold에 Target 1 존재
- `recall_ge_0.70` 운영점 산출 가능

통과 조합은 다음 순서로 비교한다.

1. 전체 OOF AUPRC
2. `Target_1 vs Target_0A` AUPRC
3. fold별 성능 안정성
4. recall 70%에서 precision
5. recall 70%에서 selected rate와 FN
6. top 10%·20% 산불 포착률
7. Brier score와 log loss

최고 AUPRC와 차이가 `0.005` 이내인 피처셋들은 성능이 유사한 후보군으로 묶는다. 성능이 유사하면 다음 원칙을 적용한다.

- `WS_CORE`와 `WS_ALL` 성능이 같으면 변수 수가 적은 `WS_CORE` 우선
- 캐나다지수 추가 전후 성능이 같으면 캐나다지수를 사용하지 않는 단순 모델 우선
- `CANADA_CORE`와 `CANADA_ALL` 성능이 같으면 `CANADA_CORE` 우선
- 토지피복 추가효과가 없으면 `LC_NONE` 우선
- 특정 fold에서만 좋은 조합은 우선순위를 낮춤

Step 1 결과로 각 단일 모델의 상위 피처셋과 전체 상위 `모델 × 피처셋 × 불균형 설정` 조합을 선정한다. 성능이 명확하게 낮거나 fold 안정성이 떨어지는 조합은 다음 튜닝 단계에서 제외한다.

앙상블은 Step 1의 단일 모델 성능보다 실제로 개선되는지를 후속 단계에서 비교한다. 따라서 Step 1 결과는 이후 앙상블 성능의 기준선이 된다.

대상 조합: `random_forest + WS_CORE__CANADA_ALL__LC_USED + balanced`

inner OOF에서 threshold를 정하고 outer-validation에 적용한 더 보수적인 `recall_ge_0.70` 결과는 다음과 같다.

| 기준 | recall | precision | selected rate | TP | FP | FN |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| inner OOF threshold → outer validation | 0.7199 | 0.4060 | 16.16% | 1,118 | 1,636 | 435 |

보고서에서는 full OOF threshold 값만 단독으로 쓰기보다, threshold 선택 과정이 낙관적으로 보이지 않도록 inner OOF 기반 결과도 함께 제시하는 것이 적절하다.

이 표에서 중요한 점은 기본 threshold 0.50을 사용하면 precision은 0.8903으로 높지만 recall이 0.3973에 그친다는 것이다. 산불을 놓치면 안 된다는 목적에는 부적합하다. 따라서 이 문제에서는 `0.50` 고정 threshold를 최종 운영 기준으로 쓰면 안 된다.

`recall ≥ 0.70` 운영점은 전체 표본의 약 14.87%를 위험 표본으로 선택하면서 실제 산불의 70.06%를 포착한다. 더 보수적인 inner OOF threshold 방식에서는 selected rate가 16.16%, precision이 0.4060으로 약간 낮아지지만 recall은 0.7199로 목표를 넘는다. 이 값이 실제 보고서에서 가장 설명하기 쉬운 운영점이다.

`recall ≥ 0.90` 이상으로 올리면 FN은 크게 줄지만 selected rate가 32.43% 이상으로 증가한다. 즉 산불 누락을 더 줄일 수는 있지만 점검 대상이 크게 늘어난다. 이 결과는 모델이 하나의 정답 분류기가 아니라 위험도 기반 screening 도구라는 점을 보여준다.

동일한 모델·다른 축 조건을 맞춰 pairwise로 비교한 AUPRC 변화는 다음과 같다.

캐나다지수는 이번 Step 1에서 가장 일관적인 추가효과를 보였다. 특히 `CANADA_ALL`은 모든 pair에서 `CANADA_NONE`보다 AUPRC가 높았다. 따라서 캐나다지수를 제외하는 방향은 현재 결과로는 우선순위가 낮다.

토지피복도 평균적으로 도움이 되지만 모든 경우에 항상 좋은 것은 아니다. 반면 `WS_ALL`은 평균 개선폭이 작고 최고 조합도 `WS_CORE`를 사용하므로, 약한 보조 날씨·공간 변수를 반드시 많이 넣을 필요는 없다.

class weight의 경우 평균적으로 `balanced`가 불리했다. 그러나 최고 조합은 `random_forest + balanced`였으므로, 불균형 옵션은 모델별로 판단한다.

이 표는 Step 2 피처셋 범위를 줄이는 근거로 사용한다. `CANADA_ALL`의 평균 개선폭이 가장 크고 모든 pair에서 개선됐으므로, Step 2의 주 튜닝 후보는 `CANADA_ALL` 중심으로 잡는다. 반대로 `WS_ALL`의 평균 개선폭은 작기 때문에 모든 후보를 `WS_ALL`로 확장할 필요는 없다. `WS_CORE`와 `WS_ALL`은 상위 후보 일부에서만 비교한다.

토지피복은 평균적으로 도움이 되지만 `extra_trees`의 최고 조합처럼 `LC_NONE`이 더 좋은 경우도 있다. 따라서 Step 2에서 토지피복은 무조건 고정하지 않고, 상위 조합에서 이미 좋았던 형태를 유지한다.

#### STEP 2 후보

Step 2 하이퍼파라미터 튜닝 후보는 두 갈래로 나눈다.

1. 주 튜닝 후보: Step 1에서 실제 성능이 높았던 `모델 × 피처셋 × 불균형 설정`
2. 모델별 구제 튜닝 후보: 기본 preset에서는 낮았지만 튜닝 민감도가 큰 모델의 최고 조합

전체 192개 조합을 모두 튜닝하지는 않는다. 계산량이 지나치게 크고, Step 1에서 낮았던 피처셋까지 모두 튜닝하면 선택 과정이 과도하게 복잡해진다. 반대로 상위 3~5개 조합만 튜닝하면 XGBoost나 CatBoost처럼 기본 preset에 불리한 모델을 너무 빨리 탈락시킬 수 있다. 따라서 주 튜닝과 구제 튜닝을 분리한다.

주 튜닝 후보는 다음을 우선한다.

| 우선순위 | 후보 | 이유 |
| ---: | --- | --- |
| 1 | `random_forest + WS_CORE__CANADA_ALL__LC_USED + balanced` | Step 1 전체 1위, fold 안정성 양호 |
| 2 | `random_forest + WS_ALL__CANADA_ALL__LC_USED + balanced` | 1위와 AUPRC 차이 0.0012로 거의 동일, WS_ALL 민감도 확인 |
| 3 | `lightgbm + WS_ALL__CANADA_ALL__LC_USED + none` | AUPRC 3위, AUROC·Brier·log loss가 가장 좋음 |
| 4 | `extra_trees + WS_ALL__CANADA_ALL__LC_NONE + balanced` | bagging 계열 대안, 토지피복 없이도 강함 |
| 5 | `hist_gradient_boosting + WS_ALL__CANADA_ALL__LC_USED + none` | 성능은 다소 낮지만 sklearn boosting 기준선으로 유지 가능 |

구제 튜닝 후보는 다음을 별도로 둔다.

| 후보 | Step 1 최고 AUPRC | 구제 튜닝 이유 |
| --- | ---: | --- |
| `xgboost + WS_ALL__CANADA_ALL__LC_USED + none` | 0.5416 | boosting 계열이며 하이퍼파라미터 민감도가 큼 |
| `catboost + WS_ALL__CANADA_ALL__LC_USED + none` | 0.5606 | 기본 preset 성능은 낮지만 범주형·불균형 설정 튜닝 여지 확인 |

구제 튜닝은 주 튜닝보다 짧게 수행한다. 목적은 최종 후보를 강제로 늘리는 것이 아니라, 기본 preset 때문에 불리했던 모델인지 확인하는 것이다. 구제 튜닝 후에도 AUPRC, recall 70% precision, Target_0A 성능이 상위 후보와 큰 차이를 보이면 후속 최종 후보에서는 제외한다.

#### STEP 1 결론

Step 1 기준으로는 `random_forest + WS_CORE__CANADA_ALL__LC_USED + balanced`가 가장 강한 단일 모델 후보이다. 다만 LightGBM은 확률 품질이 가장 좋으므로 최종 후보에서 제외하지 않는다.

피처셋 측면에서는 캐나다 산불지수 전체(`CANADA_ALL`)의 추가효과가 가장 명확하다. 토지피복은 대체로 도움이 되며, 전체 날씨·공간 변수(`WS_ALL`)는 추가효과가 작다. 따라서 Step 2에서는 `CANADA_ALL` 중심으로 튜닝하되, `WS_CORE`와 `WS_ALL`, `LC_USED`와 `LC_NONE`의 차이를 일부 후보에서 유지해 민감도를 확인한다.

### STEP 2-2. 튜닝 방식

- 튜닝 방법: Optuna
- split: Step 1과 동일한 outer 5-fold 유지
- 튜닝 데이터: 각 outer-train 내부 데이터
- inner CV: 각 outer-train 내부 strict group 4-fold
- 주 objective: inner OOF AUPRC 최대화
- 보조 지표:
  - `recall_ge_0.70`에서 precision
  - `Target_1 vs Target_0A` AUPRC
  - fold별 AUPRC 표준편차
  - Brier score와 log loss
- outer-validation: 하이퍼파라미터 선택에 사용하지 않음
- lockbox: Step 2에서 사용 금지

Step 2의 튜닝된 모델은 Step 1의 기본 설정 모델과 동일한 outer CV에서 다시 평가한다. 튜닝 후 성능이 실제로 개선됐는지 비교하고, 개선되지 않은 경우 기본 설정 모델을 유지한다.

### STEP 2-3. 주 튜닝과 구제 튜닝의 차이

| 구분 | 대상 | trial 수 | 판단 기준 |
| --- | --- | ---: | --- |
| 주 튜닝 | Step 1 상위권 조합 | 많게 | 최종 후보 선발 |
| 구제 튜닝 | XGBoost, CatBoost 최고 조합 | 적게 | 튜닝 후에도 경쟁 가능한지 확인 |

구제 튜닝 모델이 Step 2 후에도 다음 조건을 만족하지 못하면 후속 앙상블 후보에서 제외한다.

- AUPRC가 주 후보와 큰 차이를 보이지 않을 것
- `recall_ge_0.70` precision이 지나치게 낮지 않을 것
- `Target_0A` 성능이 개선될 것
- fold별 성능 편차가 과도하지 않을 것

### STEP 2-5. 실행 중 계산량 점검과 중간 판단

2026-06-22 실행 중 확인한 Step 2의 실제 계산량은 예상보다 크다. 현재 스크립트의 기본 설정은 주 튜닝 후보에 대해 `outer 5-fold`, 각 outer-train 내부 `inner 4-fold`, 각 outer fold별 `Optuna 40 trials`를 사용한다.

따라서 주 튜닝 후보 1개는 다음과 같은 학습량을 가진다.

```text
5 outer folds × 40 trials × 4 inner folds = 800회 inner 학습
800회 inner 학습 + 5회 outer 최종 학습 = 후보 1개당 약 805회 fit
```

구제 튜닝 후보는 `15 trials`를 사용하므로 다음과 같다.

```text
5 outer folds × 15 trials × 4 inner folds = 300회 inner 학습
300회 inner 학습 + 5회 outer 최종 학습 = 후보 1개당 약 305회 fit
```

현재 후보 7개를 모두 기본 설정으로 끝까지 실행하면 전체 fit 수는 대략 다음 규모다.

```text
주 튜닝 후보 5개 × 805회 = 4,025회
구제 튜닝 후보 2개 × 305회 = 610회
전체 약 4,635회 fit
```

이 방식은 하이퍼파라미터 선택 편향을 줄이고 outer OOF 성능을 정직하게 비교한다는 장점이 있다. 최종 단일 모델을 엄밀하게 비교해야 할 때는 좋은 구조다. 그러나 이후 앙상블까지 진행할 계획이라면, 모든 후보를 동일한 강도의 full nested tuning으로 끝까지 밀어붙이는 것은 탐색 단계에서는 비효율적일 수 있다.

| candidate_id | 상태 | 메모 |
| --- | --- | --- |
| `TUNE_RF_CORE_ALL_LC_BAL` | 완료 | 5개 outer fold 완료, elapsed `00:31:37`, `status=OK` |
| `TUNE_RF_ALL_ALL_LC_BAL` | 진행 중 | 같은 RandomForest 계열이며 feature 수가 더 많아 fold당 시간이 더 길 수 있음 |

`TUNE_RF_CORE_ALL_LC_BAL`은 feature 40개를 사용하고, `TUNE_RF_ALL_ALL_LC_BAL`은 feature 58개를 사용한다. 두 후보는 모두 RandomForest이며 피처셋만 다르므로, 앙상블 관점에서는 예측 패턴이 매우 비슷할 가능성이 있다. 따라서 두 RandomForest 후보를 모두 full tuning으로 길게 유지하는 것은 단일 모델 민감도 확인에는 의미가 있지만, 앙상블 base learner 다양성 확보 관점에서는 우선순위가 낮다.

### STEP 2-6. 당시 앙상블 전제의 STEP 2 검토 기록

이 절은 2026-06-22 당시 앙상블까지 검토하던 중간 기록이다. 현재 활성 파이프라인은 앙상블과 calibration을 제외하고, STEP 2 tuned LightGBM을 최종 score 모델로 사용한 뒤 STEP 3에서 F2 threshold를 정하고 STEP 4에서 해석하는 구조로 단순화했다. 따라서 아래 내용은 후보 다양성 진단의 배경 기록으로만 유지한다.

이후 단계에서 여러 모델을 결합하는 앙상블을 진행한다면 Step 2는 단순히 AUPRC 1위 단일 모델을 찾는 단계가 아니다. Step 2는 다음 두 목적을 동시에 가져야 한다.

1. 최고 성능 단일 모델 후보를 확인한다.
2. 앙상블에 넣을 서로 다른 base learner 후보의 OOF 예측을 확보한다.

앙상블에서는 단일 모델 AUPRC가 조금 낮더라도 다른 모델이 놓친 산불을 잡거나, top-risk 구간이 다르게 형성되는 모델이 유용할 수 있다. 따라서 Step 2의 후보 판단 기준에는 단일 성능뿐 아니라 예측 다양성도 포함해야 한다.

#### STEP 2의 threshold 해석

Step 2에서 계산하는 threshold 지표는 단일 후보의 진단용으로 유지한다. 그러나 최종 운영 threshold는 Step 2 단일 모델 기준으로 확정하지 않는다. 앙상블을 진행하면 최종 score의 분포가 단일 모델 score와 달라지므로, 최종 threshold는 앙상블 score가 확정된 뒤 development OOF에서 다시 정한다.

따라서 Step 2 threshold는 다음처럼 해석한다.

```text
Step 2 threshold = 단일 후보 진단용 참고 지표
현재 활성 파이프라인 threshold = STEP 3 F2 threshold
lockbox threshold = 현재 미사용
```

#### STEP 2 후보 선택 기준 수정

Step 2 이후 앙상블 base learner 후보는 다음 조건을 함께 보고 선별한다.

- OOF AUPRC가 최고 후보 대비 지나치게 낮지 않을 것
- `Target_1 vs Target_0A` 성능이 무너지지 않을 것
- fold별 AUPRC 편차가 과도하지 않을 것
- top-risk capture가 의미 있을 것
- 기존 상위 후보와 예측 상관이 너무 높지 않거나, unique capture가 있을 것
- `recall_ge_0.70` 운영점에서 FN 패턴이 다른 후보와 보완적일 것

결론적으로 Step 2는 `단일 모델 챔피언 선발전`이 아니라 `최고 단일 모델 후보와 앙상블 base learner 후보를 동시에 만드는 단계`로 운영한다. full nested tuning은 최종 후보에 제한적으로 사용하고, 넓은 후보군은 더 가볍게 돌려 OOF 예측과 다양성 진단을 먼저 확보한다.

#### 선택된 하이퍼파라미터의 특징

exact parameter는 후보별 `selected_params__{candidate_id}.json`에 outer fold 단위로 저장되어 있다. 주요 패턴은 다음과 같다.

| 모델 | outer fold별 선택 패턴 |
| --- | --- |
| LightGBM | `n_estimators=400~500`, `learning_rate=0.071~0.105`, `num_leaves=55~89`, 정규화는 대체로 매우 약함 |
| XGBoost | `n_estimators=150~500`, `max_depth=5~8`, `learning_rate=0.032~0.088`, subsample과 column sampling 사용 |
| CatBoost | `iterations=100~500`, `depth=6~8`; fold별 iteration 차이가 큼 |
| HGB | `max_iter=80~360`, `learning_rate=0.029~0.081`, `max_leaf_nodes=50~63` |
| RandomForest | `max_depth=24` 또는 제한 없음, `bootstrap=false`, fold별 leaf/split 규제가 달라짐 |
| ExtraTrees | `n_estimators=280~480`, `bootstrap=false`, `max_features`와 leaf 규제가 fold별로 달라짐 |

LightGBM은 많은 트리와 약한 정규화를 선택해 AUPRC를 높였지만 확률이 0과 1에 몰리는 현상도 함께 나타났다. 따라서 현재 score는 실제 발생확률이 아니라 상대적 위험점수로 표현해야 하며, 활성 파이프라인에서는 STEP 3의 F2 threshold와 STEP 4의 SHAP·오류 분석으로 해석 범위를 제한한다.

### STEP 3-3. 분석 기준

STEP 3의 목적은 모델을 다시 고르는 것이 아니라, STEP 2에서 최종 선정한 LightGBM 위험점수를 실제 운영에서 어디까지 고위험으로 볼지 정하는 것이다. 산불 예측은 일반적인 정답 분류 문제보다 “놓치지 않는 것”의 비용이 크다. 반대로 모든 표본을 고위험으로 지정하면 recall은 높아지지만 실제 점검·경보 부담이 커진다. 따라서 threshold 분석은 recall만 보지 않고, 그 recall을 얻기 위해 얼마나 많은 표본을 선택해야 하는지 함께 봐야 한다.

기본 운영점은 F2 최대점으로 둔다. F2는 recall에 precision보다 4배 큰 가중을 주는 F-score다. 즉 산불을 놓치는 FN을 더 강하게 줄이되, precision이 지나치게 무너지는 threshold는 불리하게 만든다. 이 프로젝트에서 F2를 쓰는 이유는 다음과 같다.

1. 산불 screening에서는 FN 감소가 precision 증가보다 중요하다.
2. 그러나 recall만 최대화하면 거의 모든 표본을 고위험으로 선택하는 해가 된다.
3. F2는 recall 중심 목적과 경보 부담을 동시에 반영하는 단일 기준이다.
4. 임의로 recall 70%를 고정하는 것보다, 데이터에서 precision과 recall의 균형이 가장 좋은 지점을 선택할 수 있다.

다음 지표를 함께 비교한다.

- recall
- precision
- selected rate와 selected 건수
- FP와 FN
- specificity
- FP/TP
- recall을 5% 높일 때 추가되는 TP와 FP
- 추가 FP/추가 TP
- top-risk capture

Recall 70%, 80%, 90%는 최종 기준이 아니라 민감도 비교점이다. 이 값들은 “기관이 더 많은 경보를 감당할 수 있다면 어느 정도까지 미탐을 줄일 수 있는가”를 보여주는 stress test로 사용한다.

Top-risk 분석은 threshold 분석과 목적이 다르다. Threshold 분석은 “위험점수 몇 점 이상을 고위험으로 지정할 것인가”를 정하는 방식이다. 반면 top-risk 분석은 “점검 가능한 표본 수가 먼저 정해져 있을 때 위험점수 상위 몇 %만 본다면 산불을 얼마나 포착하는가”를 보는 방식이다. 예를 들어 하루 점검 가능량이 전체 후보의 10%라면 threshold 숫자보다 top 10% capture가 더 직접적인 운영 지표가 된다.

기후지형유형별 성능은 같은 threshold가 모든 지역에서 동일하게 작동하는지 확인하기 위해 본다. 전체 recall이 높더라도 특정 기후지형유형에서 recall이 낮으면 해당 지역의 미탐 위험이 커질 수 있다. 현재 단계에서는 지역별 threshold를 따로 만들지 않지만, 전체 threshold의 한계와 적용 범위를 설명하기 위해 subgroup 확인이 필요하다.

#### STEP 2 최종 모델과의 연결 확인

STEP 3의 입력은 STEP 2에서 단일 모델 1위로 선정한 `TUNE_LGBM_ALL_ALL_LC_NONE`의 OOF 예측이다. 모델은 tuned LightGBM이고, 피처셋은 `WS_ALL__CANADA_ALL__LC_USED`, 불균형 처리는 `none`이다. 날씨·공간 변수, 캐나다 산불지수, 토지피복 변수를 포함한 동일한 58개 피처를 사용했으며 STEP 3에서 모델이나 피처셋을 새로 선택하지 않았다.

정확히 말하면 STEP 3는 하나의 전체 데이터 재학습 모델을 대상으로 한 분석이 아니다. STEP 2의 각 outer fold에서 나머지 학습 데이터로 하이퍼파라미터를 선택하고 validation fold에 예측한 5개 OOF 결과를 합쳐 사용했다. 따라서 현재 threshold는 STEP 2에서 선정한 최종 LightGBM 후보의 development OOF 운영점이며, 학습에 사용된 표본을 다시 예측해 얻은 낙관적인 in-sample threshold가 아니다.

이 연결을 통해 모델 선택과 threshold 선택의 역할도 분리된다. STEP 2에서는 AUPRC를 중심으로 LightGBM과 피처셋을 선택했고, STEP 3에서는 이미 선택된 모델의 score를 어느 지점에서 잘라 위험 대상으로 분류할지만 결정한다.

#### F2와 recall 운영점 비교

| 운영점 | threshold | recall | precision | selected rate | TP | FP | FN | F2 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| F2 최대점 | 0.019979 | 71.99% | 44.72% | 14.67% | 1,118 | 1,382 | 435 | 0.6416 |
| recall 70% | 0.024070 | 70.06% | 46.28% | 13.79% | 1,088 | 1,263 | 465 | 0.6353 |
| recall 80% | 0.006669 | 80.04% | 33.98% | 21.46% | 1,243 | 2,415 | 310 | 0.6297 |
| recall 90% | 0.001219 | 90.08% | 23.90% | 34.34% | 1,399 | 4,455 | 154 | 0.5797 |

F2는 recall을 precision보다 더 중요하게 반영하되, recall만 높이기 위해 지나치게 많은 표본을 경보 대상으로 선택하는 것도 함께 억제하는 지표다. 따라서 F2 최대점을 사용하면 “산불을 가능한 한 많이 포착한다”는 목적과 “점검 가능한 경보량을 유지한다”는 목적을 하나의 기준에서 절충할 수 있다.

F2 최대점은 사전에 recall 목표를 70%로 고정하지 않고 전체 threshold를 비교해 정해졌으며, 결과적으로 recall 약 72% 지점에 위치했다. 이 지점에서는 전체 17,045건 중 2,500건인 14.67%를 위험 대상으로 선별해 실제 산불 1,553건 중 1,118건을 포착한다. 선별된 표본의 44.72%가 실제 산불이며, 산불 435건은 threshold 아래에 남는다.

Recall 70% 운영점과 비교하면 F2 최대점은 149건을 더 선별해 산불 30건을 추가 포착하고 FP는 119건 증가한다. 즉 recall 70%보다 경보량은 소폭 늘지만 추가 산불 포착 효율이 크게 나쁘지 않고, F2도 0.6353에서 0.6416으로 높다. 이 때문에 임의의 recall 70%보다 F2 최대점을 기본 운영점으로 선택하는 것이 더 일관된 기준이다.

Recall 70%에서 80%로 높이면 산불 155건을 추가 포착하지만 FP는 1,152건 증가하고 selected rate는 13.79%에서 21.46%로 상승한다. Recall 80%에서 90%로 높이면 산불 156건을 추가 포착하지만 FP는 2,040건 증가한다.

5%p 단위로 보면 recall을 높일수록 추가 산불 1건을 포착하는 데 필요한 추가 FP가 계속 증가한다. Recall 65%에서 70%로 높일 때는 추가 TP 1건당 FP가 약 5.15건이지만, 75%에서 80%는 약 7.96건, 85%에서 90%는 약 14.51건, 90%에서 95%는 약 24.90건이다. 모델이 가장 높은 위험도로 정렬한 산불은 비교적 적은 경보로 포착할 수 있지만, 남은 산불까지 더 찾으려면 비산불 표본을 훨씬 넓게 점검해야 한다는 뜻이다.

따라서 이 데이터에서 recall 80% 이상은 미탐 감소 효과는 분명하지만 경보 대상과 FP 증가가 크다. 기본 운영점은 F2 최대점으로 두고, 실제 운영기관이 추가 경보 부담을 감당할 수 있을 때만 recall 80% 또는 90% 운영점을 선택하는 구조가 타당하다. 반대로 점검 자원이 매우 제한적이라면 recall 70% 운영점이 precision과 selected rate 측면에서는 조금 더 효율적이다.

여기서 threshold `0.019979`는 산불 발생확률 1.9979%를 의미하지 않는다. Calibration을 수행하지 않았기 때문에 이 값은 tuned LightGBM의 raw risk score를 구분하는 기준일 뿐이며, 결과는 “발생확률이 몇 % 이상”이 아니라 “위험도 score가 threshold 이상”이라고 표현해야 한다.

#### Threshold 변화 곡선

보고서 본문에는 raw threshold 자체보다 selected rate를 x축으로 둔 곡선이 더 적합하다. LightGBM raw score는 0 근처에 많이 몰려 있어 threshold를 선형 x축으로 그리면 곡선의 핵심 구간이 압축되기 때문이다. Selected rate는 “전체 표본 중 몇 %를 고위험으로 지정하는가”를 직접 보여주므로 운영 해석도 쉽다.

![selected rate 기준 threshold trade-off](outputs/step3_f2_threshold/plots/threshold_tradeoff_by_selected_rate__step3.png)

곡선에서 selected rate가 낮은 구간에서는 precision이 높지만 recall이 낮다. 선택 범위를 넓히면 recall은 계속 증가하지만 precision은 빠르게 낮아진다. F2는 이 둘의 절충값이므로 처음에는 상승하다가 selected rate 약 14.67% 지점에서 최대가 되고, 그 이후에는 recall 증가보다 precision 하락과 경보 부담 증가가 더 커져 감소한다.

이 그림에서 F2 최대점은 recall 70% 지점과 거의 붙어 있지만 완전히 같지는 않다. F2 최대점은 recall 70%보다 약간 더 많은 14.67%를 선택하고, 산불 30건을 추가 포착한다. 반면 recall 80%, 90% 지점은 오른쪽으로 크게 이동하며 F2가 낮아진다. 즉 더 높은 recall은 가능하지만, 그 대가로 점검 대상과 FP가 크게 증가한다.

#### Top-risk 포착 성능

Top-risk 평가는 threshold를 하나로 고정하지 않고 위험점수 순위 자체가 유용한지 확인하는 분석이다. 현장에서 “전체 후보 중 몇 %만 점검 가능하다”는 제약이 먼저 주어질 수 있으므로, fixed-budget 운영 관점에서는 top 5%, 10%, 20%, 30% 구간의 산불 포착률을 함께 제시해야 한다.

| top-risk 구간 | 선택 수 | 포착 산불 | 전체 산불 포착률 | 선택 구간 내 산불 비율 | lift |
| --- | ---: | ---: | ---: | ---: | ---: |
| top 5% | 853 | 729 / 1,553 | 46.94% | 85.46% | 9.38 |
| top 10% | 1,705 | 969 / 1,553 | 62.40% | 56.83% | 6.24 |
| top 20% | 3,409 | 1,220 / 1,553 | 78.56% | 35.79% | 3.93 |
| top 30% | 5,114 | 1,359 / 1,553 | 87.51% | 26.57% | 2.92 |

Top 5%만 점검해도 전체 산불의 46.94%를 포착하고, 이 구간 안의 실제 산불 비율은 85.46%다. 이는 LightGBM 점수의 최상위 구간이 실제 산불을 매우 강하게 농축하고 있음을 보여준다. Top 10%에서는 전체 산불의 62.40%를 포착하며, 선택 구간 내 산불 비율은 56.83%다.

Top-risk 비율을 20%, 30%로 넓히면 포착 산불 수는 각각 1,220건, 1,359건으로 증가하지만 선택 구간 내 산불 비율은 낮아진다. 이는 threshold 분석과 같은 trade-off다. 더 많이 보면 더 많이 잡지만, 비산불 표본도 함께 늘어난다.

F2 threshold 운영점은 전체의 14.67%인 2,500건을 선택해 산불 1,118건을 포착한다. 즉 F2 운영점은 top 10%보다 더 넓고 top 20%보다 좁은 점검 규모에 해당한다. 이 비교를 함께 제시하면 “F2 threshold가 어느 정도 점검량을 요구하는가”를 직관적으로 설명할 수 있다.

#### Threshold 교차검증 감사

각 validation fold를 제외한 나머지 네 fold에서 F2 threshold를 선택해 적용한 결과는 다음과 같다.

- threshold 범위: 0.015724~0.020089
- 통합 recall: 72.25%
- 통합 precision: 43.78%
- 통합 selected rate: 15.04%
- 통합 F2: 0.6393
- TP 1,122, FP 1,441, FN 431, TN 14,051

전체 OOF에서 직접 계산한 F2 0.6416과 교차검증 감사 F2 0.6393의 차이가 작아 threshold 선택 결과는 크게 낙관적이지 않았다. 다만 fold별 recall 범위는 68.49~79.74%로 변동이 있으므로 새 시기 데이터에서 항상 recall 72%가 보장된다고 해석하지 않는다.

#### 기후지형유형별 F2 운영 성능

기후지형유형별 평가는 모델의 최종 성능을 부풀리기 위한 추가 지표가 아니다. 전체 threshold 하나를 모든 지역에 공통 적용했을 때 특정 지역에서 미탐이 커지는지 확인하는 안전 점검이다. 전체 데이터에서 정한 동일한 F2 threshold를 각 기후지형유형에 적용한 결과는 다음과 같다.

| 기후지형유형 | recall | precision | selected rate | FP | FN | F2 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 고지·산간형 | 68.92% | 39.53% | 15.89% | 234 | 69 | 0.6000 |
| 영동 해안형 | 77.36% | 52.23% | 13.50% | 397 | 127 | 0.7057 |
| 영서 내륙형 | 68.96% | 41.42% | 15.17% | 751 | 239 | 0.6087 |

동일한 threshold에서도 영동 해안형은 recall 77.36%, precision 52.23%로 가장 효율적이지만, 고지·산간형과 영서 내륙형의 recall은 약 69%에 머문다. 따라서 전체 recall 71.99%만 제시하면 지역별 성능 차이가 가려질 수 있다. 현재 threshold는 전체 표본의 공통 운영 기준으로 사용할 수 있지만, 모든 기후지형유형에서 같은 포착률을 보장하는 기준은 아니다.

#### STEP 3 결론

STEP 3의 목적이 “STEP 2에서 선정한 최종 LightGBM 후보에 대해 임의의 recall 70% 대신 근거 있는 운영 threshold를 정하는 것”이라면 현재 분석으로 충분하다. F2 최대점, recall별 precision·selected rate·FP·FN, 5%p 단위의 추가 경보 비용, fixed-budget top-risk 포착 성능, 다른 fold에서 정한 threshold의 교차검증 감사, 기후지형유형별 차이까지 확인했기 때문이다.

따라서 보고서용 threshold 선정 분석을 위해 calibration이나 다른 지표를 의무적으로 추가할 필요는 없다. 다만 실제 서비스에 배포할 하나의 모델 파일이 필요하다면, 별도로 전체 development 데이터에 LightGBM을 재학습하고 OOF에서 정한 threshold가 재학습 모델의 score 체계에서도 그대로 적용되는지 확인하는 배포 단계가 필요하다. 이는 현재 STEP 3의 분석 누락이 아니라 모델 배포를 위한 후속 작업이다.

### STEP 4-1. 분석 목적과 해석 원칙

STEP 4의 목적은 모델이나 threshold를 다시 고르는 것이 아니다. STEP 2에서 선택한 tuned LightGBM과 STEP 3에서 선택한 F2 threshold를 고정한 뒤, 이 모델이 어떤 관측 패턴을 근거로 위험점수를 높였는지와 F2 운영점에서 발생한 FN·FP가 어떤 조건을 가졌는지 설명하는 단계다.

이번 STEP 4의 해석 기준은 다음과 같다.

### STEP 4-3. 최종 모델 효과 요약

STEP 4는 SHAP 해석만 하는 단계가 아니다. 먼저 최종 LightGBM이 실제로 산불위험 후보를 선별하는 데 어느 정도 효과가 있었는지 STEP 2·3 결과를 한 번 묶어 확인한다.

현재 개발 OOF 데이터의 Target 1 비율은 9.11%다. 무작위로 표본을 고르면 선택 구간 안의 실제 산불 비율도 대략 9.11% 수준이 기준선이다. 최종 tuned LightGBM은 OOF AUPRC 0.6932를 기록했고, 이는 양성률 기준선보다 크게 높다. 즉 모델 score는 실제 산불 표본을 위험점수 상위로 강하게 끌어올리는 순위 성능을 가진다.

운영 관점의 효과는 STEP 3에서 다음처럼 확인했다.

| 관점 | 결과 | 해석 |
| --- | ---: | --- |
| 전체 OOF AUPRC | 0.6932 | 산불 표본을 높은 score로 정렬하는 성능 |
| Target 1 vs Target 0A AUPRC | 0.7041 | 가장 어려운 hard-negative에서도 성능 유지 |
| F2 threshold 선택률 | 14.67% | 전체 표본 중 약 1/7을 고위험으로 선별 |
| F2 threshold recall | 71.99% | 실제 산불 1,553건 중 1,118건 포착 |
| F2 threshold precision | 44.72% | 고위험 선별 표본 중 실제 산불 비율 |
| top 5% precision | 85.46% | 최상위 위험군은 실제 산불이 매우 농축됨 |
| top 10% capture | 62.40% | 전체의 10%만 봐도 산불의 약 62% 포착 |

이 결과는 모델이 단순히 “0/1 정답을 맞추는 분류기”라기보다, Pole 또는 Pole-시점 표본을 산불 취약도 순서로 정렬하는 screening 모델로 유용하다는 뜻이다. 특히 top-risk 결과는 현장에서 점검 가능한 Pole 수가 제한될 때 직접적인 의미가 있다. 예를 들어 모든 후보를 동일하게 보는 대신 위험점수 상위 5% 또는 10%를 우선 점검 대상으로 둘 수 있다.

따라서 STEP 4의 나머지 분석은 “모델이 왜 효과가 있었는가”와 “성공적으로 포착한 산불과 놓친 산불은 무엇이 다른가”를 설명하는 역할을 한다. Recall, precision, selected rate 자체는 STEP 3에서 이미 확정했으므로 여기서는 반복 계산하지 않고, 동일한 F2 threshold를 고정한 상태에서 TP·FN·FP의 원변수 분포와 SHAP 기여 구조를 해석한다.

전력설비 Pole 취약성 평가 관점에서는 다음처럼 표현하는 것이 적절하다.

> 최종 LightGBM은 각 Pole 또는 Pole-시점 표본에 절대 산불 발생확률을 부여하는 모델이 아니라, 산불 발생 조건과 유사한 고위험 후보를 우선순위화하는 산불 취약도 점수 모델이다.

각 outer fold에서 해당 fold를 제외한 train 표본으로 STEP 2의 fold별 selected parameter를 적용해 LightGBM을 재학습했다. 그 다음 학습에 사용하지 않은 validation fold에 대해서만 예측과 TreeSHAP을 계산했다. 즉 SHAP도 OOF 구조를 유지한다.

| --- | ---: |

| SHAP raw-margin additivity 최대 오차 | `8.03e-13` |
| SHAP NaN | 0 |
| OOF SHAP 행 수 | 17,045 |

저장된 STEP 2 OOF score와 STEP 4에서 재학습한 fold별 LightGBM 예측이 부동소수점 오차 수준에서 일치했다. 따라서 STEP 4의 SHAP은 STEP 3에서 threshold를 정한 동일한 OOF score 구조를 설명한다고 볼 수 있다.

### STEP 4-7. SHAP 방향 해석

전체 중요도 막대는 기여도 크기만 보여주므로 방향을 알 수 없다. 방향은 변수값과 SHAP 값의 관계, 그리고 하위 25%와 상위 25% 구간의 평균 SHAP 차이로 확인했다.

| 변수 | 값이 높아질 때 모델 방향 | 하위 25% 평균 SHAP | 상위 25% 평균 SHAP | 해석 |
| --- | --- | ---: | ---: | --- |
| `log1p_도로_최단거리_m` | 위험점수 감소 | +0.702 | -1.547 | 도로에 가까울수록 고위험 방향 |
| `log1p_산림지역_최단거리_m` | 위험점수 증가 | -0.900 | +0.744 | 산림 내부보다 비산림 접경·이격 위치를 고위험으로 사용 |
| `DC` | 위험점수 증가 | -0.641 | +0.725 | 장기 건조 누적이 클수록 고위험 방향 |
| `BUI` | 위험점수 증가 | -0.710 | +0.397 | 가용 연료 건조도가 높을수록 고위험 방향 |
| `직전48h_강수량합` | 위험점수 감소 | +0.203 | -0.541 | 최근 강수 부족을 고위험 방향으로 사용 |
| `D-1_최소습도_pct` | 위험점수 감소 | +0.244 | -0.260 | 전일 최소습도가 낮을수록 고위험 방향 |
| `시점_습도_pct` | 위험점수 감소 | +0.252 | -0.274 | 기준시각 습도가 낮을수록 고위험 방향 |
| `FWI` | 위험점수 증가 | -0.341 | +0.145 | 종합 산불위험지수가 높을수록 고위험 방향 |
| `log1p_시가화거리_m` | 위험점수 감소 | +0.240 | -0.123 | 시가화 지역에 가까울수록 고위험 방향 |
| `경사도(도)` | 위험점수 감소 | +0.143 | -0.205 | 완경사 위치를 상대적 고위험으로 사용 |

이 방향은 EDA의 해석과 잘 맞는다. EDA에서는 산불 발생지가 도로·시가화·생활권 접경에 가깝고, WUI 내부에서도 완경사·하부 사면 쪽으로 치우친다고 보았다. 또한 절대 습도 하나보다 직전 24~48시간의 저습, 강수 부족, 누적 건조가 더 안정적인 신호라고 정리했다. LightGBM도 동일하게 도로·생활권 접근성과 건조·저습 조건을 고위험 방향으로 사용했다.

다만 모든 변수의 방향이 단순하지는 않다. `FFMC_10일평균`은 전체 단순 상관에서는 높은 값이 오히려 음의 SHAP과 연결되는 구간이 있었다. 이는 FFMC가 중요하지 않다는 뜻이 아니라, FFMC·DC·BUI·FWI·습도·계절 변수가 함께 들어간 LightGBM 분기 안에서 기여가 나뉘기 때문이다. 따라서 SHAP 방향은 “다른 변수들을 함께 본 모델 내부의 조건부 기여”로 해석한다.

![TP FN FP TN별 SHAP 중요도](outputs/step4_model_interpretation/plots/shap_by_error_group_heatmap.png)

이 heatmap은 `mean |SHAP|` 기준이다. 색이 진하다는 것은 해당 그룹에서 그 변수가 강하게 사용됐다는 뜻이지, 반드시 위험점수를 올렸다는 뜻은 아니다. 방향은 각 그룹의 mean SHAP을 함께 확인해야 한다.

TP는 실제 산불을 고위험으로 포착한 사례다. TP에서는 `DC`의 평균 SHAP이 +0.947로 가장 강했다. 그 다음으로 도로 최단거리 +0.705, 비산림 WUI 접경 +0.737, 산림지역 거리 +0.494, `FFMC_10일평균` +0.577, `BUI` +0.569가 위험점수를 올렸다. 즉 TP는 공간적 접근성·접경 신호와 장기 건조·단기 연료 건조 신호가 동시에 강한 사례다.

FN은 실제 산불이지만 F2 threshold 아래에 남은 사례다. FN에서도 비산림 WUI 접경(+0.628), 도로거리(+0.405), 산림지역 거리(+0.315)는 양의 기여를 보였다. 그러나 `DC`(+0.139), `BUI`(+0.134), `FFMC_10일평균`(-0.036)의 건조 신호는 TP보다 약했다. 즉 일부 산불은 공간적으로는 고위험 위치에 있었지만, 입력 시점의 건조·습도 조건이 전형적인 산불 고위험 패턴보다 약해 score가 낮아졌다.

FP는 비산불이지만 고위험으로 선택된 사례다. FP에서는 도로거리 +0.630, 산림지역 거리 +0.552, 비산림 WUI 접경 +0.699, `DC` +0.508, `BUI` +0.421이 모두 양의 방향이었다. 즉 FP는 모델 입력상 TP와 상당히 비슷한 조건을 가진 hard-negative다. 실제 산불이 발생하지 않았다는 결과만 다를 뿐, 관측된 위험조건은 강하게 갖춘 경우가 많다.

TN에서는 같은 핵심 변수들이 반대로 작동했다. 비산림 WUI 접경, 도로거리, 산림지역 거리, DC, BUI의 평균 SHAP이 모두 음수였다. 따라서 TN은 “중요 변수가 없어서 낮은 점수”가 아니라, 같은 변수들이 비위험 방향으로 점수를 낮춘 사례다.

STEP 4의 결론은 다음과 같다.

1. 최종 LightGBM의 가장 큰 예측 축은 비산림 WUI 접경, 도로 접근성, 산림지역 거리, DC·BUI 장기 건조도다.

3. 낮은 습도, 낮은 최근 강수, 높은 DC·BUI·FWI는 전반적으로 위험점수를 올리는 방향이었다.
4. TP는 공간 신호와 건조·습도 신호가 동시에 강한 사례였다.
5. FN은 공간 신호가 일부 있어도 TP보다 덜 건조하고 더 습하며 접근성 신호가 약한 산불이 많았다.
6. FN 대부분은 threshold 바로 아래가 아니므로 F2 threshold를 소폭 낮추는 것만으로 해결하기 어렵다.
7. FP의 93.27%는 Target 0A에서 발생했으며, 이는 쉬운 배경 대조군이 아니라 실제 산불과 조건이 유사한 hard-negative다.
8. 영동 해안형은 가장 효율적으로 포착됐고, 영서 내륙형은 FP 절대 수가 가장 많아 운영 부담이 크다.
9. top-risk 산불은 나머지 산불보다 장기 건조지수와 풍속이 높고 습도가 낮으며, top 30%에서는 도로·시가화 접근성과 완경사 특성도 뚜렷했다.
10. SHAP과 오류 분석은 모델·피처·threshold를 다시 바꾸는 근거가 아니라, 최종 선택된 LightGBM 위험점수의 작동 방식과 한계를 설명하는 자료로 사용한다.
11. 전력설비 Pole 적용 시에는 이 score를 실제 발생확률이 아니라 취약도 우선순위 점수로 사용하고, top 5%·10%·20% 또는 F2 threshold 이상 Pole을 고위험 후보군으로 정의한다.

최종 보고서에서는 다음처럼 압축해 쓸 수 있다.

> 최종 LightGBM은 생활권-WUI와 도로 접근성, 산림 접경 같은 공간 신호와 DC·BUI 장기 건조도, 최근 강수·습도 조건을 함께 사용했다. ## STEP 5. Pole 고정 산불 취약성 평가 계획

### STEP 5-1. 상태와 최종 결정

- 작성일: 2026-06-23
- 상태: 실행 전 계획
- 예측 대상 파일: `data/예측데이터/gangwon_poles_4326.csv`
- 현재 확인된 열: `pole_id`, `lon`, `lat`
- 좌표계: 파일명 기준 EPSG:4326으로 추정
- 최종 목적: 강원도 전력설비 Pole의 고정 산불 취약성 순위 산출
- 주 분석 기간·시간대: 10월~5월의 09~16시
- 월 범위: 10월~5월
- 현재 단계에서 실제 예측 실행: 하지 않음

STEP 5의 목적은 특정 날짜의 산불 발생확률을 예측하는 것이 아니라, 위치가 고정된 전력설비 Pole이 산불 위험관리 기간의 실제 기상 조건에서 얼마나 반복적으로 고위험 점수를 받는지 평가하는 것이다. 따라서 결과는 “오늘 산불이 발생할 확률”이 아니라 “10월~5월 09~16시 실제 날씨 조건에서의 상대 산불 취약성 순위”로 해석한다.

이번 단계에서는 기후지형유형별로 월 범위를 다르게 나누지 않고, 주 분석 기간을 10월~5월로 통일한다. 이는 EDA에서 확인한 월별 산불 집중 패턴과 통념적인 산불 위험관리 기간을 함께 반영하기 위한 결정이다. 최종 LightGBM은 모든 월·시간대가 포함된 학습자료에서 학습됐지만, 실제 적용 단계에서 평가 모집단을 10월~5월 09~16시로 제한하는 것은 가능하다. 이 경우 결과의 의미는 “연중 전체 취약성”이 아니라 “산불 위험관리 기간의 오전~오후 운영 취약성”이다.

### STEP 5-2. 왜 위치만으로 바로 예측할 수 없는가

최종 LightGBM은 단순 위치 모델이 아니다. STEP 4 SHAP에서 확인했듯이 모델은 공간·지형 변수뿐 아니라 직전 강수·습도, 풍속, DC·BUI·FWI 같은 캐나다 산불지수와 계절·시간 변수를 함께 사용한다.

반면 `gangwon_poles_4326.csv`에는 다음 정보만 있다.

| 열 | 의미 | 모델 입력 가능 여부 |
| --- | --- | --- |
| `pole_id` | 전주 식별자 | 식별용, 모델 입력 아님 |
| `lon` | 경도 | 원본 좌표, 모델에는 직접 입력하지 않음 |
| `lat` | 위도 | 원본 좌표, 모델에는 직접 입력하지 않음 |

따라서 현재 파일만으로는 다음 피처들이 비어 있다.

| 피처 축 | 예시 | 필요성 |
| --- | --- | --- |
| 기준시각 | 월, 시간, 기준시각 | 산불위험은 시점에 따라 달라짐 |
| 기상 | 습도, 강수, 풍속, 기온, 기압변동 | 최종 모델의 핵심 입력 |
| 선행 기상창 | 직전 24h·48h 평균/최소/합계 | 발생 전 건조·강수 부족 신호 |
| 캐나다 산불지수 | FFMC, DMC, DC, BUI, FWI 등 | 장기·단기 건조도 반영 |
| 기후지형유형 | 영동 해안형, 영서 내륙형, 고지·산간형 | 지역별 배경 차이 |
| 공간·지형 | 고도, 경사도, TPI, 도로거리, 시가화거리, 산림거리 | Pole 주변의 정적 취약성 |
| 토지피복 | 산림, 초지, 시가화, WUI 접경 등 | 생활권·산림 접경 구조 |

즉 현재 모델의 예측 단위는 엄밀히 말해 `Pole` 하나가 아니라 `Pole × 기준시각`이다. 같은 Pole이라도 비가 온 직후에는 위험점수가 낮을 수 있고, 장기 건조와 저습·강풍이 겹치는 시점에는 위험점수가 높아질 수 있다.

### STEP 5-3. 날씨 모집단의 정의

STEP 5에서 말하는 날씨 모집단은 단순한 기상셀 목록이 아니다. 모델에 투입되는 날씨 조건은 다음 단위다.

```text
기상셀ID × 기준시각
```

예를 들면 다음과 같다.

```text
YD_0005 × 2021-02-01 09:00
YD_0005 × 2021-02-01 10:00
YS_0012 × 2022-04-15 14:00
YS_0012 × 2022-08-20 16:00
```

각 날씨 row에는 해당 시점의 기온, 습도, 풍속, 강수량, 기압뿐 아니라 직전 24~48시간 rolling 변수와 FFMC, DMC, DC, ISI, BUI, FWI가 함께 포함되어야 한다. 사람이 `건조`, `습윤`, `강풍` 같은 가상 조합을 임의로 만드는 것이 아니라, 학습데이터를 만들 때 사용한 방식과 동일한 실제 과거 기상 row를 사용한다.

주 분석 날씨 모집단은 다음으로 정의한다.

```text
10월~5월의 사용 가능한 과거 날짜 × 09~16시 × Pole에 매칭된 기상셀의 실제 날씨 row
```

월은 10월~5월로 제한한다. 6~9월은 주 분석에서 제외하며, 최종 취약성은 10월~5월의 실제 기상 조건 안에서 상위 분위와 반복 고위험 지표로 요약한다. 따라서 결과를 해석할 때도 “연중 전체”가 아니라 “10월~5월 산불 위험관리 기간”이라는 적용 범위를 명시한다.

### STEP 5-4. 왜 10월~5월과 09~16시로 제한하는가

월을 기후지형유형별로 다르게 자르면 EDA의 세부 패턴을 더 반영할 수 있지만, 보고서의 주 분석 기준이 복잡해진다. 이번 STEP 5의 목적은 한 번의 주 분석으로 Pole 취약성 순위를 산출하는 것이므로, 강원도 산불 발생 집중과 산불 위험관리 관점이 함께 들어가는 10월~5월을 공통 기간으로 사용한다.

따라서 STEP 5에서는 다음 원칙을 적용한다.

| 선택 | 결정 | 이유 |
| --- | --- | --- |
| 월 범위 | 10월~5월 | 산불 위험관리 기간과 EDA의 월별 집중 패턴을 함께 반영 |
| 시간대 | 09~16시 | EDA에서 산불이 오전~오후에 집중됐고, 야간·새벽 조건은 주 목적을 희석할 수 있음 |
| 날씨 구성 | 실제 과거 날씨 row 사용 | 습도·온도·풍속·캐나다지수 간 관계를 깨지 않음 |
| 요약 방식 | 평균보다 p90/p95와 초과율 중심 | 저위험 날짜 때문에 취약성이 희석되는 문제를 줄임 |

10월~5월을 사용한다는 것은 해당 기간의 모든 시간을 쓰겠다는 뜻이 아니다. 주 분석은 `09시, 10시, 11시, 12시, 13시, 14시, 15시, 16시`의 실제 날씨만 사용한다. EDA에서는 오전~오후 시간대 집중이 뚜렷했고, 운영상 오후 위험 지속 가능성과 모델의 시간 변수 활용을 고려해 16시까지 포함한다.

### STEP 5-5. Pole별 feature matrix 생성 절차

Pole 예측용 feature matrix는 다음 순서로 만든다.

#### 1. Pole 위치 품질검사

- `pole_id` 중복 여부 확인
- `lon`, `lat` 결측 확인
- 좌표 범위가 강원도 주변에 있는지 확인
- EPSG:4326에서 분석용 투영좌표계로 변환
- Pole 위치가 육상·강원도 경계 안에 있는지 확인

#### 2. 기상셀 및 기후지형유형 매칭

- 각 Pole을 가장 가까운 기상셀 또는 모델링 격자에 매칭한다.
- 해당 기상셀의 `기후지형유형`을 부여한다.
- 영동 해안형, 영서 내륙형, 고지·산간형 Pole 수를 확인한다.
- 기상셀 매칭 거리가 비정상적으로 큰 Pole은 별도 점검 대상으로 표시한다.

#### 3. 정적 공간·지형·토지피복 피처 생성

Pole 위치에서 다음 변수를 만든다.

- 고도
- 경사도
- TPI
- 도로 최단거리
- 시가화지역 최단거리
- 산림지역 최단거리
- 농업지역 최단거리
- 임도 최단거리
- 등산로 최단거리
- 토지피복 대분류·중분류
- 산림유형
- 비산림 WUI 접경 후보

이 부분은 위치만으로 만들 수 있으므로 STEP 5 구현에서 가장 먼저 처리한다. 단, 최종 LightGBM은 토지피복 변수와 거리 변수의 이름·단위·`log1p` 변환 방식이 학습 때와 동일해야 한다.

#### 4. 09~16시 날씨 row 결합

각 Pole에 대해 매칭된 기상셀의 10월~5월 과거 날짜 중 09~16시 row를 결합한다.

```text
pole_id × 기준시각
```

이때 각 row에는 다음 변수가 포함되어야 한다.

- 월·시간 sin/cos
- 시점 기온, 습도, 풍속, 기압
- 직전 24h·48h 평균습도, 최소습도
- 직전 24h·48h 강수량합
- 직전 24h·48h 평균풍속, 최대풍속
- D-1, D-2, D-3 습도·강수 변수
- FFMC, FFMC 10일 평균, DMC, DC, ISI, BUI, FWI

날씨 변수는 임의 평균값으로 대체하지 않는다. 학습데이터 생성 과정과 같은 기준으로 만든 실제 과거 기상·캐나다지수 row를 사용한다.

#### 5. 최종 모델 입력 컬럼 검증

예측용 feature matrix는 학습 때 사용한 58개 피처와 이름·자료형·범주 처리가 일치해야 한다.

검증 항목은 다음이다.

- 학습 피처 58개가 모두 존재하는지
- 추가 불필요 컬럼이 모델 입력으로 들어가지 않는지
- 결측률이 과도하지 않은지
- 범주형 값이 학습 범위와 크게 어긋나지 않는지
- 거리 변수는 `log1p` 기준으로 생성됐는지
- 같은 `pole_id × 기준시각` 중복행이 없는지
- 10월~5월 외 월이 섞이지 않았는지
- 09~16시 외 시간대가 섞이지 않았는지
- 기상셀별·연도별 날씨 row 수가 과도하게 불균형하지 않은지

### STEP 5-6. Pole별 취약성 요약 지표

최종 LightGBM score는 `pole_id × 기준시각` 단위로 나온다. 그러나 보고서와 지도에는 Pole 단위의 고정 취약성 순위가 필요하므로, 여러 시점의 score를 Pole별로 요약한다.

여기서 “산불 발생 위험이 높은 Pole”을 판단하는 기준은 시간별 score의 단순 평균이 아니다. STEP 5의 목적은 10월~5월 09~16시 중 모든 시간에 평균적으로 점수가 높은 Pole을 찾는 것이 아니라, 산불 위험관리 기간 안에서 건조·강풍·누적건조 같은 고위험 조건이 왔을 때 반복적으로 높은 score를 받는 Pole을 우선 선별하는 것이다. 따라서 평균 score는 보조 지표로만 사용하고, 최종 주 순위는 상위 위험 조건을 대표하는 `p95_score`로 정한다.

주요 요약 지표는 다음과 같다.

| 지표 | 정의 | 해석 |
| --- | --- | --- |
| `p95_score` | Pole별 10월~5월 09~16시 score의 95분위수 | 고위험 조건에서 얼마나 위험해지는지 |
| `p90_score` | Pole별 10월~5월 09~16시 score의 90분위수 | 상위 10% 위험 조건의 취약성 |
| `f2_threshold_exceed_rate` | STEP 3 F2 threshold 이상인 row 비율 | 고위험 상태로 분류되는 빈도 |
| `top10_repeat_rate` | 같은 기준시각 내 top 10%에 포함된 비율 | 운영 우선점검 후보로 반복 등장하는 정도 |
| `mean_score` | Pole별 10월~5월 평균 score | 산불 위험관리 기간의 평균적 위험, 보조 지표 |
| `max_score` | Pole별 최대 score | 최악 조건 참고값, 이상치 민감 |

최종 주 순위는 `p95_score`를 기준으로 한다. 이유는 10월~5월 안에서도 비오는 날, 습한 날, 상대적으로 저위험인 날이 포함되기 때문에 단순 평균은 취약성을 희석할 수 있기 때문이다. `p95_score`는 “산불 위험관리 기간 중 위험한 조건이 왔을 때 이 Pole이 얼마나 높은 점수를 받는가”를 보여주므로 전력설비 취약성 평가 목적에 더 직접적이다.

`f2_threshold_exceed_rate`는 보조 주 지표로 함께 사용한다. 특정 Pole이 한두 번만 극단적으로 높은 점수를 받는지, 아니면 여러 날짜에서 반복적으로 F2 운영 threshold를 넘는지 구분할 수 있기 때문이다.

각 지표의 역할은 다음처럼 구분한다.

| 판단 기준 | STEP 5에서의 역할 | 주의할 점 |
| --- | --- | --- |
| `p95_score` | 최종 Pole 취약성 주 순위 | 확률 95%가 아니라 Pole별 시간 score의 95분위수 |
| `f2_threshold_exceed_rate` | 반복적으로 위험군에 들어가는 Pole 확인 | STEP 3 threshold는 OOF 기준이므로 절대 발생확률 기준이 아님 |
| `top10_repeat_rate` | 제한된 점검량에서 반복 우선순위가 높은 Pole 확인 | 같은 기준시각 안에서의 상대 순위로 해석 |
| `mean_score` | 평균적 위험 보조 설명 | 저위험 날씨가 많으면 취약 Pole의 신호가 희석될 수 있음 |
| `max_score` | 최악 조건 참고 | 한두 개 이상치에 민감하므로 주 순위로 사용하지 않음 |

따라서 STEP 5의 최종 판단 문장은 다음처럼 둔다.

> Pole별 산불 취약성은 10월~5월 09~16시 전체 score의 평균이 아니라 `p95_score`를 주 기준으로 산출한다. 이는 전력설비 취약성 평가의 목적이 평상시 평균 위험을 추정하는 것이 아니라, 산불 위험관리 기간 중 고위험 기상 조건에서 높은 위험점수를 보이는 Pole을 우선 선별하는 데 있기 때문이다.

### STEP 5-7. 취약성 등급과 지도화 기준

Pole별 최종 등급은 `p95_score` 순위를 기준으로 나눈다.

| 등급 | 정의 | 해석 |
| --- | --- | --- |
| 매우 높음 | `p95_score` top 5% | 최우선 점검 후보 |
| 높음 | top 5~10% | 우선 점검 후보 |
| 중간 | top 10~20% | 관리 후보 |
| 낮음 | 나머지 | 상대적으로 낮은 취약성 |
| 반복 고위험 | `f2_threshold_exceed_rate` 상위권 | 여러 날씨 조건에서 반복적으로 위험군 |

지도에는 `p95_score` 기반 등급을 기본으로 표시하고, 별도 레이어로 `f2_threshold_exceed_rate` 또는 `top10_repeat_rate`를 표시한다. 이렇게 하면 특정 극한 조건에서만 위험한 Pole과 여러 조건에서 반복적으로 위험한 Pole을 구분할 수 있다.

`top 5%`, `top 10%`, `top 20%` 등급은 자연적인 절대 위험 임계값이 아니라 우선점검을 위한 운영 등급이다. 이 기준을 사용하는 근거는 STEP 3 top-risk 분석이다. 최종 LightGBM OOF에서 위험점수 상위 5%는 전체 산불의 46.94%, 상위 10%는 62.40%, 상위 20%는 78.56%를 포착했다. 즉 이 모델의 score 상위 구간은 실제 산불 표본을 강하게 농축했다. 따라서 Pole 적용에서도 “발생확률 몇 % 이상”이라는 식의 절대 확률 해석보다, `p95_score` 기준 상위 Pole을 점검 우선순위로 정하는 방식이 더 적절하다.

단, STEP 5의 top-risk 등급은 Pole 전체 모집단 내부의 상대 순위다. 학습 OOF의 top-risk capture가 Pole 예측 데이터에서 동일하게 재현된다는 뜻은 아니다. 그러므로 보고서에서는 `매우 높음`, `높음` 같은 등급을 “산불 발생 확정”이 아니라 “산불 위험관리 기간에 우선 점검할 상대적 고위험 Pole”로 표현한다.

### STEP 5-8. 배포용 모델과 threshold 문제

현재 STEP 2~4의 성능은 5-fold OOF 결과다. 이는 평가에는 적합하지만, 실제 Pole 예측을 위해 저장된 단일 배포용 fitted model을 의미하지 않는다.

Pole 예측을 하려면 다음 중 하나를 선택해야 한다.

| 방식 | 설명 | 장단점 |
| --- | --- | --- |
| 전체 development 재학습 모델 | 17,045행 전체로 LightGBM을 다시 학습 | 단일 모델이라 배포가 단순하지만 OOF threshold와 score 분포 차이를 확인해야 함 |
| 5-fold 모델 ensemble | STEP 2 outer fold별 parameter로 5개 모델을 학습해 평균 score 사용 | 안정적일 수 있지만 score 분포가 OOF 단일-fold score와 달라질 수 있음 |

어떤 방식을 쓰든 STEP 3의 F2 threshold `0.0199793963`을 그대로 적용하기 전에 score 분포 점검이 필요하다. 특히 Pole 전체 예측은 학습 OOF와 표본 구성, 공간 분포, 양성률 개념이 다르므로 F2 threshold는 절대 확률 기준이 아니라 학습 score 체계에서 정한 운영 참고선으로 사용한다.

### STEP 5-9. 계산량과 실행 방식

주 분석은 `Pole 수 × 10월~5월 09~16시 row 수` 규모가 된다. 따라서 전체 feature matrix를 한 번에 메모리에 올리지 않고, 기상셀 또는 날짜 chunk 단위로 나누어 계산한다.

권장 실행 방식은 다음과 같다.

1. Pole별 정적 피처는 한 번만 계산해 저장한다.
2. 10월~5월 09~16시 날씨 row는 기상셀·연도 또는 월 단위로 chunk를 나눈다.
3. 각 chunk에서 `pole_id × 기준시각` feature matrix를 만들고 score를 계산한다.
4. 원본 row별 score는 필요한 최소 열만 저장한다.
5. Pole별 집계 지표는 streaming 방식으로 누적하거나 중간 parquet/CSV를 합산한다.

실제 구현 전에 1개 기상셀 또는 Pole 일부를 대상으로 파일럿을 실행해 feature 생성, 결측, score 분포, 처리 시간을 먼저 점검한다. 단, 최종 보고용 취약성 순위는 파일럿 샘플이 아니라 10월~5월 09~16시 전체 기준으로 산출한다.

### STEP 5-12. STEP 5 결론

`data/예측데이터/gangwon_poles_4326.csv`는 현재 위치자료만 포함하므로 최종 LightGBM에 바로 투입할 수 없다. 이 모델은 위치·지형·토지피복과 기준시각의 기상·캐나다 산불지수를 함께 사용하는 `Pole × 기준시각` 위험도 모델이기 때문이다.

최종 적용 방향은 다음으로 확정한다.

```text
10월~5월의 사용 가능한 과거 날짜 09~16시 실제 날씨
× Pole별 정적 공간·지형·토지피복 피처
→ Pole × 기준시각 LightGBM score 산출
→ Pole별 p95_score, F2 threshold 초과율, top-risk 반복 포함률로 취약성 순위화
```

보고서에서는 다음 문장으로 정리할 수 있다.

> 최종 LightGBM은 위치만으로 산불위험을 예측하는 정적 확률 모델이 아니라, 위치·지형·토지피복과 기준시각의 기상·건조도 조건을 결합해 상대적 산불 취약도 score를 산출하는 모델이다. STEP 5에서는 10월~5월의 09~16시 실제 날씨를 각 Pole에 결합한 뒤, Pole별 p95 score와 반복 고위험 비율을 사용해 전력설비의 고정 산불 취약성 순위를 산출한다. 이 결과는 실제 발생확률이 아니라 산불 위험관리 기간의 top-risk 기반 점검 우선순위로 해석한다.
