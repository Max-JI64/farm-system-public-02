# 머신러닝 학습 로그

## 1. 문서 목적

이 문서는 `jsw/Analysis/new_machine_learning/머신러닝_학습_계획.md`에 따라 실제로 수행한 학습 과정, 산출물, 평가지표와 단계별 판단을 기록한다.

각 단계에서는 다음 원칙을 지킨다.

- 모델을 한 종류씩 실행하고 결과를 별도 파일로 저장한다.
- development 데이터의 outer OOF 예측으로 모델과 피처셋을 비교한다.
- threshold는 outer-validation 정답을 직접 보고 정하지 않고 inner OOF에서 정한다.
- lockbox는 최종 모델·피처셋·calibration·threshold가 확정되기 전까지 사용하지 않는다.
- 실행 전 계획과 실행 후 결과를 구분하여 기록한다.

## Step 1. 여러 단일 모델 피처셋 screening

### Step 1 상태

- 작성일: 2026-06-22
- 상태: 실행 전 계획
- 목적: 앙상블 전에 여러 머신러닝 모델을 각각 독립적으로 학습하고 모델·피처셋 조합별 성능을 비교
- 모델 단위: 각 알고리즘을 서로 결합하지 않은 단일 모델

Step 1에서 실행할 단일 머신러닝 모델은 다음 6개다.

| model_name | 역할 |
| --- | --- |
| `HistGradientBoosting` | sklearn 기반 비선형 boosting 기준 |
| `LightGBM` | 빠른 boosting 및 불균형 처리 |
| `XGBoost` | 규제가 가능한 boosting 비교 |
| `CatBoost` | 범주형 변수가 포함된 데이터 비교 |
| `RandomForest` | bagging 계열 기준 |
| `ExtraTrees` | 무작위성이 큰 bagging 비교 |

여기서 `단일 모델`은 하나의 알고리즘만 실행한다는 뜻이 아니다. 위 6개 모델을 각각 따로 학습하며, 모델들의 예측값을 평균·가중평균·stacking 등으로 결합하지 않는다는 뜻이다. 단일 모델 결과가 확보된 뒤에만 후속 단계에서 앙상블의 추가효과를 비교한다.

Step 1에서는 각 모델의 기본 설정과 사전에 정한 불균형 처리 설정만 비교한다. 모든 피처셋을 동일한 기본 모델 조건에서 공정하게 screening하기 위해 하이퍼파라미터 튜닝은 하지 않는다.

하이퍼파라미터 튜닝은 Step 2에서 수행한다. Step 1에서 탈락한 전체 192개 조합을 모두 튜닝하지는 않되, 성능 상위 조합만 너무 좁게 튜닝하지도 않는다. Step 2는 `주 튜닝 후보`와 `모델별 구제 튜닝 후보`를 분리해 진행한다.

SHAP 기반 변수 제거, 모델 결합, calibration과 lockbox 평가도 Step 1에서는 수행하지 않는다.

### Step 1-1. 입력 데이터와 분할

- 입력 데이터: `data/학습데이터/최종_머신러닝_학습데이터.csv`
- 목적변수: `Target`
- 개발 데이터: 모델·피처셋 비교와 OOF 예측 생성에 사용
- lockbox: Step 1에서 접근 및 평가 금지
- outer CV: strict group 5-fold
- inner CV: 각 outer-train 내부의 strict group 4-fold
- 분할 단위: 계획서에서 정의한 `date_exposure_component_group`

모든 피처셋과 불균형 설정은 동일한 split manifest를 사용한다. 조합마다 fold를 새로 만들지 않는다.

다음 변수는 모델 입력 `X`에서 제외한다.

- `Target`
- `샘플ID`, `기준시각`, `기상셀ID`
- `샘플유형`, `실험안`, `시간샘플링방식`, `공간층`
- `fire_id`, `원본_fire_id`, `후보점ID`, `source_fire_id`
- `모델링_그룹ID`
- `캐나다지수_기준날짜`, `캐나다지수_정책`
- `위도`, `경도`
- 그 밖에 변수사전에서 `X 제외`로 지정한 변수

`샘플유형`은 모델 입력에는 사용하지 않고 `Target_0A`, `Target_0B1`, `Target_0B2` subgroup 평가에만 사용한다.

### Step 1-2. 비교할 피처셋

각 단일 모델에 다음 세 실험 축을 완전 교차한 동일한 16개 피처셋을 적용한다.

| 토지피복 | `LC_NONE`, `LC_USED` | 2 |

2 × 4 × 2 = 16개 피처셋

4. `WS_CORE__CANADA_ALL__LC_NONE`
5. `WS_CORE__CANADA_NONE__LC_USED`
6. `WS_CORE__CANADA_CORE__LC_USED`
7. `WS_CORE__CANADA_LONG__LC_USED`
8. `WS_CORE__CANADA_ALL__LC_USED`
9. `WS_ALL__CANADA_NONE__LC_NONE`
10. `WS_ALL__CANADA_CORE__LC_NONE`
11. `WS_ALL__CANADA_LONG__LC_NONE`
12. `WS_ALL__CANADA_ALL__LC_NONE`
13. `WS_ALL__CANADA_NONE__LC_USED`
14. `WS_ALL__CANADA_CORE__LC_USED`

### Step 1-3. 불균형 처리 설정

Target 1 비율이 약 9.1%이므로 다음 두 설정을 비교한다.

| imbalance_option | 설정 |
| --- | --- |
| `none` | class weight 미적용 |
| `balanced` | `class_weight="balanced"` |

각 단일 모델의 비교 단위는 다음과 같다.

```text
16개 피처셋 × 2개 불균형 설정 = 32개 조합
```

6개 단일 모델 전체의 주 비교 조합은 다음과 같다.

```text
6개 모델 × 16개 피처셋 × 2개 불균형 설정 = 192개 조합
```

기존 `샘플가중치`를 적용하는 실험은 기본 class weight 결과를 확인한 뒤 별도 민감도 실험으로 진행한다. Step 1에서는 SMOTE를 사용하지 않는다.

### Step 1-4. 전처리와 모델 설정

전처리는 각 outer-train 안에서만 학습하여 validation 정보가 들어오지 않도록 pipeline으로 구성한다.

- 수치형 변수: 숫자형 변환과 결측 처리
- 범주형 변수: 학습 fold에서만 범주 인코딩
- 월·시간·풍향: 계획서에서 정의한 sin·cos 변수 사용
- 거리 변수: 기본적으로 `log1p` 변수를 사용하고 원본과 중복 투입하지 않음
- 토지피복: 범주형 표현과 이진 flag를 동시에 중복 투입하지 않음
- 변수 선택과 전처리 fitting: 반드시 train fold 내부에서만 수행

각 모델의 하이퍼파라미터는 사전에 정한 기본 설정으로 고정한다. 이 단계에서는 모델·피처셋의 넓은 비교가 목적이므로 피처셋마다 서로 다른 튜닝 결과를 적용하지 않는다.

모델별 고정 설정과 random seed는 실행 스크립트와 각 모델의 `run_manifest.json`에 저장한다.

### Step 1-5. 학습과 OOF 예측 생성

각 `모델 × 피처셋 × 불균형 설정` 조합에서 다음 순서로 실행한다.

1. outer 5-fold를 순회한다.
2. outer-train 데이터만 사용해 전처리와 모델을 학습한다.
3. 학습에 사용하지 않은 outer-validation의 산불위험 예측값을 생성한다.
4. 5개 fold의 예측값을 합쳐 development 전체 OOF 예측을 만든다.
5. 각 표본에 OOF 예측이 정확히 한 번 존재하는지 검사한다.

순위 성능용 outer 모델의 예정 학습 횟수는 다음과 같다.

```text
6개 모델 × 16개 피처셋 × 2개 불균형 설정 × outer 5-fold = 960회
```

정직한 threshold 평가를 위해 각 outer fold에서는 추가로 다음 절차를 수행한다.

1. outer-train을 inner 4-fold로 나눈다.
2. inner OOF 예측으로 threshold 후보를 정한다.
3. outer-train 전체로 모델을 다시 학습한다.
4. 미리 정한 threshold를 outer-validation에 적용한다.
5. outer-validation의 실제 recall, precision, FN과 selected rate를 기록한다.

inner OOF threshold 산출에는 `192 × outer 5 × inner 4 = 3,840회`의 추가 학습이 필요하다. outer 모델 960회를 합치면 Step 1의 예정 fit 횟수는 최대 4,800회다. 모델별 조기 실패나 지원하지 않는 불균형 옵션이 있을 수 있으므로 실행 로그에는 예정 횟수와 별도로 실제 성공·실패 fit 수와 소요시간을 기록한다.

### Step 1-7. 계산할 평가지표

#### 전체 OOF 순위·확률 지표

- AUPRC
- AUROC
- Brier score
- log loss
- fold별 AUPRC 평균·표준편차
- group bootstrap 95% CI

#### Threshold 운영점

- `fixed_0.50`
- `best_f1`
- `best_f2`
- `recall_ge_0.70`
- `recall_ge_0.90`
- `recall_ge_0.95`

각 운영점에서 다음 값을 저장한다.

- threshold
- TP, FP, FN, TN
- recall, precision, specificity
- false positive rate
- F1, F2
- balanced accuracy, MCC
- selected_n, selected_rate
- FP per TP

#### Subgroup 평가

- `Target_1 vs Target_0A` AUPRC
- `Target_1 vs Target_0B1` AUPRC
- `Target_1 vs Target_0B2` AUPRC
- 기후지형유형별 AUPRC와 recall

#### Top-risk 평가

- 상위 5%, 10%, 20%, 30%
- 선택 표본 수
- 실제 산불 포착 수
- capture rate
- precision
- lift

### Step 1-8. 결과 판단 규칙

Step 1에서는 단일 지표만으로 모델이나 피처셋을 탈락시키지 않는다.

필수 통과 조건은 다음과 같다.

- split 누수 0건
- OOF 예측 누락·중복 0건
- 예측값 NaN·inf 0건
- 모든 outer fold에 Target 1 존재
- `recall_ge_0.70` 운영점 산출 가능

통과 조합은 다음 순서로 비교한다.

1. 전체 OOF AUPRC
2. `Target_1 vs Target_0A` AUPRC
3. fold별 성능 안정성
4. recall 70%에서 precision
5. recall 70%에서 selected rate와 FN
6. top 10%·20% 산불 포착률
7. Brier score와 log loss

최고 AUPRC와 차이가 `0.005` 이내인 피처셋들은 성능이 유사한 후보군으로 묶는다. 성능이 유사하면 다음 원칙을 적용한다.

- `WS_CORE`와 `WS_ALL` 성능이 같으면 변수 수가 적은 `WS_CORE` 우선
- 캐나다지수 추가 전후 성능이 같으면 캐나다지수를 사용하지 않는 단순 모델 우선
- `CANADA_CORE`와 `CANADA_ALL` 성능이 같으면 `CANADA_CORE` 우선
- 토지피복 추가효과가 없으면 `LC_NONE` 우선
- 특정 fold에서만 좋은 조합은 우선순위를 낮춤

Step 1 결과로 각 단일 모델의 상위 피처셋과 전체 상위 `모델 × 피처셋 × 불균형 설정` 조합을 선정한다. 성능이 명확하게 낮거나 fold 안정성이 떨어지는 조합은 다음 튜닝 단계에서 제외한다.

앙상블은 Step 1의 단일 모델 성능보다 실제로 개선되는지를 후속 단계에서 비교한다. 따라서 Step 1 결과는 이후 앙상블 성능의 기준선이 된다.

- 양성률: 9.11%
- outer CV: `모델링_그룹ID` 기준 strict group 5-fold

의존성 점검 결과 `sklearn`, `lightgbm`, `xgboost`, `catboost`는 모두 사용 가능했다.

실시간 진행 표시는 이후 실행부터 `tqdm` 막대바를 사용하도록 스크립트를 수정했다. 기본 실행에서는 전체 fit 진행률과 현재 모델 fit 진행률을 막대바로 표시한다. `tqdm`이 없거나 막대바가 불편한 환경에서는 `--no-progress-bar` 옵션으로 기존 텍스트 로그를 사용할 수 있다.

#### 최고 조합의 threshold 운영점

대상 조합: `random_forest + WS_CORE__CANADA_ALL__LC_USED + balanced`

full OOF 전체에서 threshold를 정했을 때의 운영점은 다음과 같다.

| operating point | threshold | recall | precision | selected rate | TP | FP | FN |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| fixed 0.50 | 0.5000 | 0.3973 | 0.8903 | 4.07% | 617 | 76 | 936 |
| best F1 | 0.3655 | 0.5319 | 0.6726 | 7.20% | 826 | 402 | 727 |
| best F2 | 0.2267 | 0.7663 | 0.3705 | 18.84% | 1,190 | 2,022 | 363 |
| recall ≥ 0.70 | 0.2611 | 0.7006 | 0.4292 | 14.87% | 1,088 | 1,447 | 465 |
| recall ≥ 0.90 | 0.1316 | 0.9002 | 0.2529 | 32.43% | 1,398 | 4,130 | 155 |
| recall ≥ 0.95 | 0.0818 | 0.9504 | 0.2021 | 42.85% | 1,476 | 5,828 | 77 |

inner OOF에서 threshold를 정하고 outer-validation에 적용한 더 보수적인 `recall_ge_0.70` 결과는 다음과 같다.

| 기준 | recall | precision | selected rate | TP | FP | FN |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| inner OOF threshold → outer validation | 0.7199 | 0.4060 | 16.16% | 1,118 | 1,636 | 435 |

보고서에서는 full OOF threshold 값만 단독으로 쓰기보다, threshold 선택 과정이 낙관적으로 보이지 않도록 inner OOF 기반 결과도 함께 제시하는 것이 적절하다.

이 표에서 중요한 점은 기본 threshold 0.50을 사용하면 precision은 0.8903으로 높지만 recall이 0.3973에 그친다는 것이다. 산불을 놓치면 안 된다는 목적에는 부적합하다. 따라서 이 문제에서는 `0.50` 고정 threshold를 최종 운영 기준으로 쓰면 안 된다.

`recall ≥ 0.70` 운영점은 전체 표본의 약 14.87%를 위험 표본으로 선택하면서 실제 산불의 70.06%를 포착한다. 더 보수적인 inner OOF threshold 방식에서는 selected rate가 16.16%, precision이 0.4060으로 약간 낮아지지만 recall은 0.7199로 목표를 넘는다. 이 값이 실제 보고서에서 가장 설명하기 쉬운 운영점이다.

`recall ≥ 0.90` 이상으로 올리면 FN은 크게 줄지만 selected rate가 32.43% 이상으로 증가한다. 즉 산불 누락을 더 줄일 수는 있지만 점검 대상이 크게 늘어난다. 이 결과는 모델이 하나의 정답 분류기가 아니라 위험도 기반 screening 도구라는 점을 보여준다.

이 표는 threshold를 하나로 정하지 않고 위험도 순위 자체가 유용한지 확인하는 결과다. top 5%만 보아도 전체 산불의 44.8%를 포착하고, top 10%에서 60.0%, top 20%에서 77.8%를 포착한다. 이는 모델 점수가 실제 산불 위험을 높은 순서로 정렬하는 데 의미가 있음을 보여준다.

운영 관점에서는 두 가지 방식이 가능하다. 하나는 `recall ≥ 0.70`처럼 목표 recall을 정하고 threshold를 선택하는 방식이고, 다른 하나는 하루 또는 지역별 점검 가능량에 맞춰 top 10%·20%를 우선 점검하는 방식이다. 보고서에는 두 방식을 모두 제시하면 threshold 선택의 임의성을 줄일 수 있다.

#### 피처 축별 효과

동일한 모델·다른 축 조건을 맞춰 pairwise로 비교한 AUPRC 변화는 다음과 같다.

| 비교 축 | 평균 AUPRC 변화 | 중앙값 변화 | 좋아진 pair 수 | 해석 |
| --- | ---: | ---: | ---: | --- |
| `CANADA_CORE - CANADA_NONE` | +0.0194 | +0.0161 | 48 / 48 | 캐나다지수 핵심만 넣어도 일관된 개선 |
| `CANADA_LONG - CANADA_NONE` | +0.0294 | +0.0269 | 48 / 48 | 장기 건조지수도 예측정보 있음 |
| `CANADA_ALL - CANADA_NONE` | +0.0402 | +0.0370 | 48 / 48 | 가장 강하고 일관된 개선 |
| `LC_USED - LC_NONE` | +0.0164 | +0.0207 | 80 / 96 | 토지피복은 대체로 도움 |
| `WS_ALL - WS_CORE` | +0.0057 | +0.0037 | 72 / 96 | 전체 날씨·공간 변수의 추가효과는 작음 |
| `balanced - none` | -0.0106 | -0.0090 | 32 / 96 | class weight는 평균적으로 불리하지만 일부 모델에는 도움 |

캐나다지수는 이번 Step 1에서 가장 일관적인 추가효과를 보였다. 특히 `CANADA_ALL`은 모든 pair에서 `CANADA_NONE`보다 AUPRC가 높았다. 따라서 캐나다지수를 제외하는 방향은 현재 결과로는 우선순위가 낮다.

토지피복도 평균적으로 도움이 되지만 모든 경우에 항상 좋은 것은 아니다. 반면 `WS_ALL`은 평균 개선폭이 작고 최고 조합도 `WS_CORE`를 사용하므로, 약한 보조 날씨·공간 변수를 반드시 많이 넣을 필요는 없다.

class weight의 경우 평균적으로 `balanced`가 불리했다. 그러나 최고 조합은 `random_forest + balanced`였으므로, 불균형 옵션은 모델별로 판단한다.

이 표는 Step 2 피처셋 범위를 줄이는 근거로 사용한다. `CANADA_ALL`의 평균 개선폭이 가장 크고 모든 pair에서 개선됐으므로, Step 2의 주 튜닝 후보는 `CANADA_ALL` 중심으로 잡는다. 반대로 `WS_ALL`의 평균 개선폭은 작기 때문에 모든 후보를 `WS_ALL`로 확장할 필요는 없다. `WS_CORE`와 `WS_ALL`은 상위 후보 일부에서만 비교한다.

토지피복은 평균적으로 도움이 되지만 `extra_trees`의 최고 조합처럼 `LC_NONE`이 더 좋은 경우도 있다. 따라서 Step 2에서 토지피복은 무조건 고정하지 않고, 상위 조합에서 이미 좋았던 형태를 유지한다.

#### Step 2 후보

Step 2 하이퍼파라미터 튜닝 후보는 두 갈래로 나눈다.

1. 주 튜닝 후보: Step 1에서 실제 성능이 높았던 `모델 × 피처셋 × 불균형 설정`
2. 모델별 구제 튜닝 후보: 기본 preset에서는 낮았지만 튜닝 민감도가 큰 모델의 최고 조합

전체 192개 조합을 모두 튜닝하지는 않는다. 계산량이 지나치게 크고, Step 1에서 낮았던 피처셋까지 모두 튜닝하면 선택 과정이 과도하게 복잡해진다. 반대로 상위 3~5개 조합만 튜닝하면 XGBoost나 CatBoost처럼 기본 preset에 불리한 모델을 너무 빨리 탈락시킬 수 있다. 따라서 주 튜닝과 구제 튜닝을 분리한다.

주 튜닝 후보는 다음을 우선한다.

| 우선순위 | 후보 | 이유 |
| ---: | --- | --- |
| 1 | `random_forest + WS_CORE__CANADA_ALL__LC_USED + balanced` | Step 1 전체 1위, fold 안정성 양호 |
| 2 | `random_forest + WS_ALL__CANADA_ALL__LC_USED + balanced` | 1위와 AUPRC 차이 0.0012로 거의 동일, WS_ALL 민감도 확인 |
| 3 | `lightgbm + WS_ALL__CANADA_ALL__LC_USED + none` | AUPRC 3위, AUROC·Brier·log loss가 가장 좋음 |
| 4 | `extra_trees + WS_ALL__CANADA_ALL__LC_NONE + balanced` | bagging 계열 대안, 토지피복 없이도 강함 |
| 5 | `hist_gradient_boosting + WS_ALL__CANADA_ALL__LC_USED + none` | 성능은 다소 낮지만 sklearn boosting 기준선으로 유지 가능 |

구제 튜닝 후보는 다음을 별도로 둔다.

| 후보 | Step 1 최고 AUPRC | 구제 튜닝 이유 |
| --- | ---: | --- |
| `xgboost + WS_ALL__CANADA_ALL__LC_USED + none` | 0.5416 | boosting 계열이며 하이퍼파라미터 민감도가 큼 |
| `catboost + WS_ALL__CANADA_ALL__LC_USED + none` | 0.5606 | 기본 preset 성능은 낮지만 범주형·불균형 설정 튜닝 여지 확인 |

구제 튜닝은 주 튜닝보다 짧게 수행한다. 목적은 최종 후보를 강제로 늘리는 것이 아니라, 기본 preset 때문에 불리했던 모델인지 확인하는 것이다. 구제 튜닝 후에도 AUPRC, recall 70% precision, Target_0A 성능이 상위 후보와 큰 차이를 보이면 Step 3 앙상블 후보에서는 제외한다.

#### Step 1 결론

Step 1 기준으로는 `random_forest + WS_CORE__CANADA_ALL__LC_USED + balanced`가 가장 강한 단일 모델 후보이다. 다만 LightGBM은 확률 품질이 가장 좋으므로 최종 후보에서 제외하지 않는다.

피처셋 측면에서는 캐나다 산불지수 전체(`CANADA_ALL`)의 추가효과가 가장 명확하다. 토지피복은 대체로 도움이 되며, 전체 날씨·공간 변수(`WS_ALL`)는 추가효과가 작다. 따라서 Step 2에서는 `CANADA_ALL` 중심으로 튜닝하되, `WS_CORE`와 `WS_ALL`, `LC_USED`와 `LC_NONE`의 차이를 일부 후보에서 유지해 민감도를 확인한다.

### Step 2-2. 튜닝 방식

- 튜닝 방법: Optuna
- split: Step 1과 동일한 outer 5-fold 유지
- 튜닝 데이터: 각 outer-train 내부 데이터
- inner CV: 각 outer-train 내부 strict group 4-fold
- 주 objective: inner OOF AUPRC 최대화
- 보조 지표:
  - `recall_ge_0.70`에서 precision
  - `Target_1 vs Target_0A` AUPRC
  - fold별 AUPRC 표준편차
  - Brier score와 log loss
- outer-validation: 하이퍼파라미터 선택에 사용하지 않음
- lockbox: Step 2에서 사용 금지

Step 2의 튜닝된 모델은 Step 1의 기본 설정 모델과 동일한 outer CV에서 다시 평가한다. 튜닝 후 성능이 실제로 개선됐는지 비교하고, 개선되지 않은 경우 기본 설정 모델을 유지한다.

### Step 2-3. 주 튜닝과 구제 튜닝의 차이

| 구분 | 대상 | trial 수 | 판단 기준 |
| --- | --- | ---: | --- |
| 주 튜닝 | Step 1 상위권 조합 | 많게 | 최종 후보 선발 |
| 구제 튜닝 | XGBoost, CatBoost 최고 조합 | 적게 | 튜닝 후에도 경쟁 가능한지 확인 |

구제 튜닝 모델이 Step 2 후에도 다음 조건을 만족하지 못하면 후속 앙상블 후보에서 제외한다.

- AUPRC가 주 후보와 큰 차이를 보이지 않을 것
- `recall_ge_0.70` precision이 지나치게 낮지 않을 것
- `Target_0A` 성능이 개선될 것
- fold별 성능 편차가 과도하지 않을 것

### Step 2-5. 실행 중 계산량 점검과 중간 판단

2026-06-22 실행 중 확인한 Step 2의 실제 계산량은 예상보다 크다. 현재 스크립트의 기본 설정은 주 튜닝 후보에 대해 `outer 5-fold`, 각 outer-train 내부 `inner 4-fold`, 각 outer fold별 `Optuna 40 trials`를 사용한다.

따라서 주 튜닝 후보 1개는 다음과 같은 학습량을 가진다.

```text
5 outer folds × 40 trials × 4 inner folds = 800회 inner 학습
800회 inner 학습 + 5회 outer 최종 학습 = 후보 1개당 약 805회 fit
```

구제 튜닝 후보는 `15 trials`를 사용하므로 다음과 같다.

```text
5 outer folds × 15 trials × 4 inner folds = 300회 inner 학습
300회 inner 학습 + 5회 outer 최종 학습 = 후보 1개당 약 305회 fit
```

현재 후보 7개를 모두 기본 설정으로 끝까지 실행하면 전체 fit 수는 대략 다음 규모다.

```text
주 튜닝 후보 5개 × 805회 = 4,025회
구제 튜닝 후보 2개 × 305회 = 610회
전체 약 4,635회 fit
```

이 방식은 하이퍼파라미터 선택 편향을 줄이고 outer OOF 성능을 정직하게 비교한다는 장점이 있다. 최종 단일 모델을 엄밀하게 비교해야 할 때는 좋은 구조다. 그러나 이후 앙상블까지 진행할 계획이라면, 모든 후보를 동일한 강도의 full nested tuning으로 끝까지 밀어붙이는 것은 탐색 단계에서는 비효율적일 수 있다.

| --- | --- | --- |
| `TUNE_RF_CORE_ALL_LC_BAL` | 완료 | 5개 outer fold 완료, elapsed `00:31:37`, `status=OK` |

`TUNE_RF_CORE_ALL_LC_BAL`은 feature 40개를 사용하고, `TUNE_RF_ALL_ALL_LC_BAL`은 feature 58개를 사용한다. 두 후보는 모두 RandomForest이며 피처셋만 다르므로, 앙상블 관점에서는 예측 패턴이 매우 비슷할 가능성이 있다. 따라서 두 RandomForest 후보를 모두 full tuning으로 길게 유지하는 것은 단일 모델 민감도 확인에는 의미가 있지만, 앙상블 base learner 다양성 확보 관점에서는 우선순위가 낮다.

### Step 2-6. 앙상블 전제의 Step 2 수정 방향

이후 단계에서 여러 모델을 결합하는 앙상블을 진행한다면 Step 2는 단순히 AUPRC 1위 단일 모델을 찾는 단계가 아니다. Step 2는 다음 두 목적을 동시에 가져야 한다.

1. 최고 성능 단일 모델 후보를 확인한다.
2. 앙상블에 넣을 서로 다른 base learner 후보의 OOF 예측을 확보한다.

앙상블에서는 단일 모델 AUPRC가 조금 낮더라도 다른 모델이 놓친 산불을 잡거나, top-risk 구간이 다르게 형성되는 모델이 유용할 수 있다. 따라서 Step 2의 후보 판단 기준에는 단일 성능뿐 아니라 예측 다양성도 포함해야 한다.

#### Step 2의 threshold 해석

Step 2에서 계산하는 threshold 지표는 단일 후보의 진단용으로 유지한다. 그러나 최종 운영 threshold는 Step 2 단일 모델 기준으로 확정하지 않는다. 앙상블을 진행하면 최종 score의 분포가 단일 모델 score와 달라지므로, 최종 threshold는 앙상블 score가 확정된 뒤 development OOF에서 다시 정한다.

따라서 Step 2 threshold는 다음처럼 해석한다.

```text
Step 2 threshold = 단일 후보 진단용 참고 지표
앙상블 이후 threshold = 최종 운영 기준 후보
lockbox threshold = development에서 고정한 threshold를 그대로 적용한 최종 확인 결과
```

#### Step 2 후보 선택 기준 수정

Step 2 이후 앙상블 base learner 후보는 다음 조건을 함께 보고 선별한다.

- OOF AUPRC가 최고 후보 대비 지나치게 낮지 않을 것
- `Target_1 vs Target_0A` 성능이 무너지지 않을 것
- fold별 AUPRC 편차가 과도하지 않을 것
- top-risk capture가 의미 있을 것
- 기존 상위 후보와 예측 상관이 너무 높지 않거나, unique capture가 있을 것
- `recall_ge_0.70` 운영점에서 FN 패턴이 다른 후보와 보완적일 것

| XGBoost - HGB | 0.9022 | 상당히 유사 |
| XGBoost - CatBoost | 0.9163 | 중복성이 큼 |
| RF_CORE tuned - RF_ALL tuned | 0.9193 | 두 RF를 함께 넣을 필요가 낮음 |
| LightGBM - XGBoost | 0.9197 | 순위는 매우 유사하지만 확률 품질 역할은 다름 |

두 RandomForest 후보는 Pearson 0.9509, Spearman 0.9193으로 거의 중복이다. 둘을 동시에 앙상블에 넣는 것보다 성능이 더 좋은 한 개만 사용하는 것이 적절하다.

ExtraTrees는 단일 성능이 낮지만 LightGBM과 Spearman 0.7483으로 가장 다른 후보 중 하나다. 따라서 ExtraTrees는 단일 우승 후보가 아니라 다양성 전용 예비 base로 의미가 있다.

#### LightGBM이 놓친 산불의 추가 포착

LightGBM과 다른 후보의 top 10% 위험군을 합쳤을 때 결과는 다음과 같다.

| 추가 후보 | 해당 후보 단독 포착 | LightGBM 단독 포착 | union 포착 | LightGBM 대비 추가 포착 |
| --- | ---: | ---: | ---: | ---: |
| RF_CORE tuned | 919 | 969 | 1,058 | +89 |
| RF_ALL tuned | 937 | 969 | 1,055 | +86 |
| ExtraTrees | 905 | 969 | 1,047 | +78 |
| HGB | 917 | 969 | 1,045 | +76 |
| CatBoost | 926 | 969 | 1,044 | +75 |
| XGBoost | 933 | 969 | 1,031 | +62 |

LightGBM 단독 top 10%는 전체 산불의 62.40%를 포착한다. RF_CORE tuned와의 단순 union은 1,058건, 즉 68.13%까지 올라간다. 이것이 곧바로 평균 앙상블 성능을 보장하는 것은 아니지만, LightGBM이 놓친 산불을 다른 알고리즘이 실제로 포착하고 있음을 보여준다.

동일한 `recall ≥ 0.70` threshold에서도 후보마다 포착한 Target 1이 완전히 같지 않았다. LightGBM이 놓친 산불 중 RF_CORE tuned가 130건, ExtraTrees가 121건, RF_ALL tuned가 107건, HGB가 103건, CatBoost가 97건, XGBoost가 85건을 각각 추가 포착했다. 따라서 Step 4에서 단일 AUPRC만으로 base를 고르면 이 보완성을 잃을 수 있다.

Step 1 기본 RF_CORE와 tuned LightGBM을 별도로 비교하면 Spearman은 0.8252였다. top 10%에서 기본 RF는 LightGBM이 놓친 산불 86건을 추가 포착했고, 두 후보의 union은 1,055건이었다. tuned RF보다 Step 1 기본 RF의 단일 성능이 높으므로 실제 앙상블에서는 Step 1 기본 RF를 우선한다.

#### Step 3·4로 넘길 후보

| 후보 | 결정 | 다음 단계 역할 |
| --- | --- | --- |
| tuned LightGBM | 선택 | 단일 모델 1위, Step 3 주 ablation 대상, Step 4 핵심 base |
| Step 1 기본 RF_CORE | 선택 | 가장 좋은 RandomForest 버전, bagging 대표 base |
| tuned XGBoost | 선택 | log loss 최저, 구제 튜닝 성공, 확률 품질 보조 base |
| tuned ExtraTrees | 예비 | 단일 성능은 낮지만 다양성 확인용 base |
| tuned HGB | 예비 | 높은 recall 운영점 보조, 안정성 기준 후보 |
| tuned CatBoost | 보류 | fold 불안정성과 XGBoost 중복성 때문에 1차 조합 제외 |
| tuned RF_CORE | 교체 | Step 1 기본 RF_CORE보다 낮아 tuned 버전 미채택 |
| tuned RF_ALL | 제외 | Step 1보다 낮고 RF_CORE와 중복 |

Step 3 피처 ablation은 모든 후보에 반복하지 않는다. 우선 LightGBM을 주 대상으로 하고, 알고리즘 계열 비교가 필요할 때 Step 1 기본 RF_CORE와 XGBoost 또는 ExtraTrees를 제한적으로 추가한다. Step 1 기본 RF를 ablation할 때는 Optuna parameter JSON이 아니라 Step 1의 고정 preset을 그대로 적용해 같은 outer split에서 다시 학습한다.

Step 4의 1차 앙상블 입력은 `LightGBM + Step1 RF_CORE + XGBoost`로 시작한다. 단순 평균과 기하평균에서 개선이 작으면 다양성이 큰 ExtraTrees를 추가한 조합을 비교한다. HGB는 recall 90% 운영점 또는 top 30% 포착 개선을 확인하는 예비 후보로 둔다.

#### Step 2 결론

Step 2의 최고 단일 위험 순위 모델은 `TUNE_LGBM_ALL_ALL_LC_NONE`이다. AUPRC 0.6932, Target_0A AUPRC 0.7041, top 10% 산불 포착률 62.40%, recall 70% selected rate 13.79%로 주요 기준에서 가장 강했다.

다만 LightGBM의 raw 확률은 극단적이고 log loss가 나쁘므로 아직 최종 산불 발생확률 모델로 확정하지 않는다. 현재 단계에서 채택하는 것은 LightGBM의 순위 성능이며, calibration과 최종 threshold는 앙상블 확정 후 다시 평가한다.

튜닝은 boosting 계열에 효과적이었고 RandomForest와 ExtraTrees에는 효과가 없었다. 따라서 최종 후보는 무조건 Step 2 tuned 버전만 쓰지 않고 Step 1과 Step 2 중 알고리즘별 최선의 버전을 사용한다.

다음 단계는 제한적 Step 3 피처 ablation이다. 이후 Step 4에서 OOF 예측을 조합해 단일 LightGBM보다 실제로 개선되는 앙상블이 있는지 확인한다. 앙상블 개선이 작거나 불안정하면 LightGBM 단일 모델을 최종 후보로 유지한다.

## Step 3 예정. 제한적 피처 ablation

원래 학습 계획에서 Step 3에 해당하는 단계는 앙상블이 아니라 피처 ablation이다. 피처 ablation은 최종 후보 모델에서 특정 변수 묶음을 제거하고 다시 OOF 성능을 비교해, 어떤 정보 축이 실제 예측 성능에 기여하는지 확인하는 실험이다.

다만 Step 2의 계산량이 이미 크기 때문에 Step 3를 모든 모델과 모든 후보에 대해 full nested tuning으로 반복하지 않는다. Step 3는 다음 목적에 맞게 제한적으로 수행한다.

1. 최종 후보가 특정 변수 묶음에 과하게 의존하는지 확인한다.
2. 캐나다지수, 토지피복, 기상, 지형·거리, 계절·시간 축의 실제 기여도를 보고서에 설명할 수 있게 한다.
3. 성능이 거의 유지되는 더 단순한 피처셋이 있는지 확인한다.
4. 앙상블에 넣을 후보들이 서로 다른 정보 축을 사용하는지 확인한다.

### Step 3-1. 실행 대상

Step 3는 Step 2 결과가 나온 뒤 다음 후보에만 수행한다.

| 대상 | 기준 |
| --- | --- |
| 단일 모델 1위 후보 | Step 2 OOF AUPRC, Target_0A, top-risk, fold 안정성을 종합해 선정 |
| 앙상블 base 대표 후보 | 서로 다른 알고리즘 계열에서 2~3개 이내 선정 |
| 필요 시 보조 후보 | 단일 성능은 낮아도 unique capture가 큰 후보 |

RandomForest 후보가 2개 모두 남더라도 둘 다 ablation하지 않는다. 둘의 예측이 비슷하면 `RF_CORE` 또는 `RF_ALL` 중 Step 2 결과가 더 좋은 하나만 ablation한다.

### Step 3-2. ablation 실험 목록

기본 ablation은 다음 변수 묶음 단위로 수행한다.

| ablation_id | 제거 또는 제한 내용 | 목적 |
| --- | --- | --- |
| `DROP_CANADA_ALL` | 캐나다 산불지수 전체 제거 | 캐나다지수의 총 기여도 확인 |
| `DROP_LANDCOVER` | 토지피복 변수 제거 | 토지피복이 실제 예측에 필요한지 확인 |
| `DROP_WEATHER` | 날씨 변수 제거 | 단기 기상 정보의 기여도 확인 |
| `DROP_TERRAIN_DISTANCE` | 지형·거리·접근성 변수 제거 | 공간 조건의 기여도 확인 |
| `DROP_SEASON_TIME` | 계절·월·시간 변수 제거 | 시간적 패턴 의존도 확인 |

캐나다지수는 내부 중복이 크므로, 단일 모델 1위 후보에 한해 다음 민감도도 확인한다.

| ablation_id | 내용 |
| --- | --- |
| `CANADA_FWI_ONLY` | FWI만 사용 |
| `CANADA_FFMC_FWI` | FFMC + FWI |
| `CANADA_CORE_EDA` | FFMC + ISI + FWI |
| `CANADA_LONG_TERM_SENSITIVITY` | DMC + DC + BUI |
| `CANADA_LEAVE_ONE_INDEX_OUT` | 캐나다지수 7개를 하나씩 제거 |

### Step 3-3. 학습 방식

Step 3는 피처셋이 바뀌므로 기존 Step 2 OOF 확률값만 조합해서 처리할 수 없다. 변수 묶음을 제거하면 모델 입력이 달라지므로, 해당 ablation 피처셋으로 OOF 예측을 새로 생성해야 한다.

하지만 하이퍼파라미터 튜닝까지 매번 새로 크게 돌리지는 않는다.

우선순위는 다음과 같다.

1. Step 2에서 선택된 후보의 outer fold별 best parameter를 재사용한다.
2. 같은 outer split에서 ablated feature set으로만 다시 학습해 OOF 예측을 만든다.
3. 기준 모델 대비 AUPRC, Target_0A, top-risk, recall 70% 운영점이 얼마나 변하는지 본다.
4. ablation 모델이 기준 모델보다 좋아지는 예외적 결과가 나오면, 그때만 제한적 Optuna 재튜닝을 검토한다.

여기서 재사용하는 best parameter는 Step 2 출력 파일인 `selected_params__{candidate_id}.json`의 `selected_params_by_outer_fold`에 저장된 값이다. Step 2는 fitted model 객체 자체를 저장하는 단계가 아니므로, Step 3에서 Step 2 모델을 그대로 불러와 변수만 제거하는 방식은 아니다. 각 ablation 실험은 같은 outer split을 유지하되, fold별로 저장된 Step 2 best parameter를 적용해 새 피처셋으로 pipeline을 다시 fit하고 validation fold의 OOF 확률을 다시 만든다.

예를 들어 `TUNE_RF_CORE_ALL_LC_BAL`의 fold 0 ablation은 `selected_params__TUNE_RF_CORE_ALL_LC_BAL.json` 안의 fold 0 parameter를 읽고, fold 0의 outer-train에서 ablated feature set으로 모델을 새로 학습한 뒤 fold 0 validation에 예측한다. 따라서 Step 3를 실행하려면 해당 base candidate의 Step 2 후보 실행이 `CANDIDATE DONE`까지 완료되어 `selected_params__*.json`과 `oof__*.csv`가 저장되어 있어야 한다.

즉 Step 3의 기본 목적은 “최적 성능 탐색”이 아니라 “정보 축의 기여도 확인”이다. 따라서 Step 2와 같은 full tuning을 반복하지 않는다.

### Step 3-4. 저장할 결과

Step 3 결과는 다음 폴더에 저장한다.

```text
jsw/Analysis/new_machine_learning/outputs/step3_feature_ablation/
```

저장 파일은 다음을 기본으로 한다.

| 파일 | 내용 |
| --- | --- |
| `ablation_manifest.csv` | 실행한 기준 후보, ablation_id, 제거 변수 묶음, feature 수 |
| `oof__{base_candidate_id}__{ablation_id}.csv` | ablation별 OOF 예측 |
| `summary__step3_feature_ablation.csv` | 기준 모델 대비 성능 변화 |
| `threshold_metrics__step3_feature_ablation.csv` | 단일 후보 진단용 threshold 지표 |
| `top_risk_metrics__step3_feature_ablation.csv` | top-risk capture 변화 |
| `subgroup_metrics__step3_feature_ablation.csv` | Target_0A와 기후지형유형별 변화 |

Step 3 결과 해석에서는 다음을 우선한다.

- `DROP_CANADA_ALL`에서 성능이 크게 떨어지면 캐나다지수 기여도가 크다고 본다.
- `DROP_LANDCOVER`에서 성능 변화가 작으면 토지피복은 설명 보조 또는 특정 모델 보조로 해석한다.
- 특정 축을 제거했는데 성능이 좋아지면, 그 축은 과적합 또는 잡음 가능성이 있으므로 Step 4 앙상블 후보에서 제외 또는 축소 피처셋 후보로 검토한다.
- ablation 결과는 변수의 인과효과가 아니라 예측 기여도로 해석한다.

## Step 4 예정. 앙상블

Step 4의 앙상블은 Step 2와 Step 3에서 생성한 development OOF 예측값을 사용해 진행한다. 여기서 중요한 원칙은 다음과 같다.

```text
개발 단계 앙상블 비교 = Step 2/3에서 저장한 각 행별 OOF 확률값을 조합
최종 lockbox 적용 = 선택된 base 모델을 development 전체로 다시 학습한 뒤 lockbox 확률을 생성하고 같은 조합식을 적용
```

즉 Step 4에서 앙상블 후보를 비교할 때는 base 모델을 처음부터 다시 학습하지 않는다. 이미 Step 2에서 각 표본에 대해 “그 표본을 학습에 사용하지 않은 모델”이 낸 OOF 확률값을 저장했기 때문이다. 이 OOF 확률값을 후보별로 가로로 붙인 matrix를 만들고, 그 확률값들을 평균, 기하평균, 가중평균, stacking 등으로 조합한다.

단, 최종 lockbox 평가를 할 때는 lockbox 표본에 대한 base model 확률이 필요하다. 이때는 선택된 base 모델들을 development 전체로 다시 학습해 lockbox 예측확률을 만든 뒤, Step 4에서 확정한 앙상블 조합식을 그대로 적용한다. lockbox 결과를 보고 조합식이나 threshold를 다시 바꾸지 않는다.

### Step 4-1. 입력 데이터

Step 4의 기본 입력은 Step 2에서 만든 다음 파일이다.

```text
oof_matrix__step2_base_candidates.csv
```

이 파일은 후보별 OOF 예측을 한 행에 모은 matrix다.

| 열 | 설명 |
| --- | --- |
| `sample_id` | 표본 식별자 |
| `y_true` | 실제 Target |
| `outer_fold` | OOF fold |
| `sample_type` | subgroup 평가용 표본유형 |
| `climate_type` | 기후지형유형 |
| `pred_{candidate_id}` | 각 base 후보의 OOF 예측확률 |

Step 3에서 ablation 후보가 실제로 좋아지거나 중요한 비교 후보가 되면, Step 3 OOF 예측도 별도 후보 열로 추가할 수 있다. 그러나 설명용 ablation 결과를 모두 앙상블 후보에 넣지는 않는다.

### Step 4-2. base learner 선택

앙상블에는 모든 Step 2 후보를 무조건 넣지 않는다. base learner는 다음 기준으로 3~5개 정도만 선택한다.

- 단일 OOF AUPRC가 상위권일 것
- Target_0A 성능이 지나치게 낮지 않을 것
- fold별 성능 편차가 과도하지 않을 것
- top 10%, 20% capture가 의미 있을 것
- 다른 후보와 예측 상관이 너무 높지 않거나 unique capture가 있을 것
- 같은 알고리즘 계열의 거의 중복 후보는 하나만 남길 것

예상되는 1차 후보군은 다음과 같다.

| 계열 | 후보 예시 | 역할 |
| --- | --- | --- |
| RandomForest | `TUNE_RF_CORE_ALL_LC_BAL` 또는 `TUNE_RF_ALL_ALL_LC_BAL` 중 1개 | 강한 bagging 기준 |
| LightGBM | `TUNE_LGBM_ALL_ALL_LC_NONE` | 확률 품질과 boosting 대표 |
| ExtraTrees | `TUNE_ET_ALL_ALL_NO_LC_BAL` | RandomForest와 다른 bagging 변형 |
| HistGradientBoosting | `TUNE_HGB_ALL_ALL_LC_NONE` | sklearn boosting 기준 |
| XGBoost/CatBoost | rescue 결과가 좋아질 때만 | 보조 후보 |

### Step 4-3. 먼저 비교할 단순 앙상블

가장 먼저 학습 없는 단순 조합을 비교한다. 이 단계는 base 모델 재학습도, Optuna도 필요 없다.

| ensemble_id | 방식 | 설명 |
| --- | --- | --- |
| `mean_top2` | 산술평균 | 상위 2개 후보 확률 평균 |
| `mean_top3` | 산술평균 | 상위 3개 후보 확률 평균 |
| `mean_diverse3` | 산술평균 | 성능과 다양성을 함께 고려한 3개 평균 |
| `geomean_diverse3` | 기하평균 | 후보들이 동시에 높게 본 표본을 강하게 올림 |
| `rank_average_diverse3` | rank 평균 | 확률 크기보다 순위 조합에 집중 |
| `max_diverse3` | 최대값 | 한 모델이라도 강하게 위험으로 본 표본을 올림. recall 보조 진단용 |

이 중 `rank_average`는 ranking score로만 취급한다. rank 평균은 AUPRC와 top-risk capture에는 유용할 수 있지만, 값 자체가 확률로 해석되기 어렵다. 따라서 최종 threshold와 calibration 후보는 원칙적으로 `mean` 또는 `geomean` 계열에서 고른다.

### Step 4-4. Optuna 가중치 앙상블을 쓸 경우

앙상블 가중치를 Optuna로 찾는 것은 가능하다. 다만 같은 OOF matrix 전체에서 가중치를 고르고 같은 OOF matrix 전체로 성능을 평가하면 개발 성능이 과대평가될 수 있다.

따라서 Optuna 가중치 앙상블은 다음 조건에서만 사용한다.

1. 단순 평균 또는 기하평균이 단일 최고 모델보다 개선되는 조짐이 있을 것
2. base 후보가 3~5개 이내일 것
3. fold-aware 방식으로 가중치 선택 편향을 줄일 것

fold-aware Optuna 절차는 다음과 같다.

```text
1. outer_fold 0을 검증 fold로 둔다.
2. 나머지 4개 fold의 OOF matrix에서 Optuna로 ensemble weight를 찾는다.
3. 찾은 weight를 outer_fold 0의 base prediction에 적용해 ensemble score를 만든다.
4. outer_fold 1~4에 대해서도 같은 과정을 반복한다.
5. 5개 fold의 ensemble score를 합쳐 ensemble OOF 성능을 계산한다.
```

이 방식은 base 모델을 다시 학습하는 것이 아니라, 이미 저장된 base OOF 확률값 위에서 조합 가중치만 학습하는 것이다. 따라서 계산량은 base model tuning보다 훨씬 작다.

가중치 탐색 대상은 다음으로 제한한다.

| ensemble_id | Optuna가 조정하는 값 |
| --- | --- |
| `weighted_mean` | 후보별 비음수 weight, 합계 1 |
| `weighted_geomean` | clipping된 확률의 log 평균 weight |
| `weighted_rank_average` | 후보별 rank weight, ranking 진단용 |

Optuna objective는 기본적으로 AUPRC를 사용하되, 다음 보조 지표를 함께 저장한다.

- `recall_ge_0.70`에서 precision과 selected rate
- Target_0A AUPRC
- fold별 AUPRC 표준편차
- top 10%, 20% capture
- Brier score와 log loss

Step 4에서 Optuna는 base 모델 하이퍼파라미터를 다시 튜닝하는 것이 아니다. 이미 만들어진 base 예측값을 어떤 비율로 섞을지만 정한다.

#### Step 4-4 보충. Optuna 사용 여부와 Step 2 full tuning의 관계

Step 4에서 Optuna 가중치 앙상블은 사용할 수 있지만, 기본 출발점은 아니다. 앙상블은 다음 순서로 진행한다.

1. 먼저 Optuna 없이 단순 평균, 기하평균, rank 평균을 비교한다.
2. 단순 조합이 단일 최고 모델보다 좋아지는 조짐이 있을 때만 Optuna로 조합 가중치를 찾는다.
3. Optuna를 쓰더라도 base 모델을 다시 학습하거나 하이퍼파라미터를 다시 튜닝하지 않는다.
4. Optuna는 Step 2에서 저장된 OOF 예측확률의 비율만 조정한다.

따라서 최고의 앙상블 조합을 찾기 위해 Step 2의 모든 후보를 full nested tuning으로 돌릴 필요는 없다. 앙상블 성능은 모든 base 모델이 극한까지 튜닝되었는지보다, 각 base 모델이 충분한 성능을 가지면서 서로 다른 오류 패턴과 top-risk 포착 패턴을 가지는지에 더 크게 좌우된다.

Step 2의 역할은 모든 모델을 끝까지 세게 튜닝하는 것이 아니라, 다음 조건을 만족하는 base 후보의 OOF 예측을 확보하는 것이다.

- 단일 성능이 충분히 높을 것
- 서로 다른 알고리즘 계열을 포함할 것
- fold별 성능이 안정적일 것
- 다른 후보와 예측 상관이 너무 높지 않을 것
- unique capture 또는 top-risk 보완성이 있을 것

`XGBoost`와 `CatBoost`는 Step 2 성능이 낮게 나오더라도 무조건 Step 4에서 사용하는 것은 아니다. 낮은 단일 성능을 가진 후보가 앙상블에 들어갈 수 있는 경우는 다음 조건 중 일부를 만족할 때다.

- 다른 상위 모델과 OOF 예측 상관이 낮다.
- 다른 모델이 놓친 Target 1을 일부 포착한다.
- top 10%, top 20% 위험군 overlap이 낮다.
- `recall_ge_0.70` 운영점에서 FN 패턴이 다르다.
- 특정 subgroup 또는 기후지형유형에서 보완적이다.

반대로 AUPRC가 낮고, unique capture도 없고, 다른 모델과 비슷하게 틀리면 Step 4 조합 후보에서 제외한다. “모든 조합을 찾는다”는 말은 모든 약한 모델까지 강제로 넣는다는 뜻이 아니라, 통과 기준을 만족한 3~5개 base 후보 안에서 조합을 비교한다는 뜻이다.

실무적인 운영 규칙은 다음과 같다.

```text
Step 2: 모든 모델 full tuning이 아니라, 대표 base 후보의 OOF 예측 확보
Step 4-1: 단순 평균/기하평균/rank 평균 먼저 비교
Step 4-2: 단순 조합 개선이 보이면 fold-aware Optuna로 weight만 탐색
Step 4-3: XGBoost/CatBoost는 diversity나 unique capture가 있을 때만 포함
```

### Step 4-5. stacking 사용 조건

stacking은 base 예측확률을 입력으로 하는 작은 meta model을 학습하는 방식이다. 예를 들어 logistic regression이 다음 입력을 받아 최종 score를 만든다.

```text
pred_RF, pred_LGBM, pred_ET, pred_HGB
```

stacking은 표현력이 더 크지만 과적합 위험도 크다. 현재 표본 수와 양성 비율을 고려하면, Step 4에서는 stacking을 기본 채택하지 않는다. 다음 조건을 만족할 때만 비교한다.

- 단순 평균/기하평균보다 fold-aware OOF 성능이 안정적으로 좋아질 것
- meta model은 logistic regression 같은 단순 모델로 제한할 것
- base 후보 수를 3~5개 이내로 제한할 것
- lockbox를 보기 전에 stacking 채택 여부를 확정할 것

stacking도 마찬가지로 base 모델을 다시 학습하는 단계가 아니다. 개발 단계에서는 Step 2 OOF matrix를 meta model 입력으로 사용한다. 최종 lockbox 적용 시에는 development 전체로 재학습한 base 모델들이 만든 lockbox 확률을 meta model에 넣는다.

### Step 4-6. 앙상블 선택 기준

앙상블은 단일 최고 모델보다 반드시 좋아야 채택한다. 단일 모델 성능이 충분하고 앙상블 개선이 작거나 불안정하면 단일 모델을 최종 후보로 유지한다.

앙상블 채택 기준은 다음과 같다.

- 단일 최고 모델보다 OOF AUPRC가 개선될 것
- `recall_ge_0.70` 운영점에서 precision이 개선되거나 selected rate가 줄어들 것
- top 10%, 20% capture가 개선될 것
- Target_0A 성능이 악화되지 않을 것
- fold별 성능이 특정 fold 하나에만 의존하지 않을 것
- Brier score와 log loss가 크게 나빠지지 않을 것
- 조합 방식이 보고서에서 설명 가능할 것

개선폭이 아주 작으면 더 단순한 모델을 우선한다. 예를 들어 앙상블 AUPRC가 단일 모델보다 `0.001`만 높고 threshold 운영점이 비슷하면 단일 모델을 유지한다. 반대로 AUPRC 개선이 작아도 top-risk capture나 recall 70% selected rate가 의미 있게 좋아지면 앙상블을 후보로 남긴다.
