# STEP 3 이후 머신러닝 파이프라인 재설계 계획

## 1. 재설계 목적

STEP 1과 STEP 2에서 모델 비교와 튜닝은 이미 AUPRC를 기준으로 완료했으며, 최종 단일 모델은 `TUNE_LGBM_ALL_ALL_LC_NONE`이다. 이후 단계에서는 모델을 다시 선택하거나 앙상블하지 않는다.

활성 파이프라인의 남은 의사결정은 다음 두 가지다.

1. tuned LightGBM score를 어느 threshold에서 운영할지 결정한다.
2. 결정된 F2 threshold를 기준으로 모델과 오류 사례를 해석한다.

## 2. 단계 구조

| 단계 | 역할 | 핵심 기준 |
| --- | --- | --- |
| STEP 1 | 단일 모델 screening | OOF AUPRC 중심 |
| STEP 2 | 단일 모델 튜닝과 최종 모델 선정 | inner OOF AUPRC |
| STEP 3 | F2 threshold와 recall 민감도 분석 | F2, recall, precision, selected rate, FP, FN |
| STEP 4 | 최종 LightGBM 해석과 오류 분석 | F2 기준 TP·FP·FN·TN, TreeSHAP |

기존 feature ablation, 앙상블, calibration 및 recall 70% 기준 해석 결과는 `archive/legacy_ablation_pipeline_20260623/`에만 보존한다.

## 3. Calibration을 제외하는 이유

Calibration은 무조건 필요한 절차가 아니다. 다음 경우에 필요하다.

- score `0.2`를 실제 발생확률 20%처럼 해석해야 할 때
- 서로 다른 시기나 모집단에서 동일한 확률 cutoff를 운영해야 할 때
- 확률 기반 비용 계산이나 의사결정을 해야 할 때

현재 목적은 tuned LightGBM 내부 score의 순위를 이용해 F2 threshold를 정하는 것이다. F2와 recall·precision·selected rate는 calibration 없이 raw score로 계산할 수 있다.

따라서 보고서에서는 raw score를 실제 산불 발생확률이라고 표현하지 않고 `위험 score` 또는 `위험 순위 score`로 표현한다. 이 조건에서 calibration은 활성 분석에서 제외한다.

## 4. STEP 3: F2 threshold와 recall 민감도 분석

입력은 STEP 2의 다음 OOF 하나다.

`outputs/step2_tuned_single_models/oof__TUNE_LGBM_ALL_ALL_LC_NONE.csv`

기본 운영점은 전체 development OOF에서 F2가 최대가 되는 threshold다. F2는 recall을 precision보다 더 중요하게 반영하는 단일 기준이며, recall 70%처럼 목표치를 먼저 임의로 고정하지 않는다.

다음 결과를 함께 비교한다.

- F2 최대점
- recall 70%, 80%, 90%
- recall 50~95% 구간의 5% 단위 민감도 표
- precision
- selected rate와 selected 건수
- FP, FN, specificity
- FP/TP
- recall을 5% 높일 때 추가되는 TP, FP와 추가 FP/추가 TP

각 outer validation fold는 제외하고 나머지 네 fold에서 threshold를 정한 뒤 남겨둔 fold에 적용한다. 이 교차검증 감사 결과는 전체 OOF에서 직접 고른 threshold의 낙관성을 점검하는 용도다.

## 5. STEP 4: 최종 LightGBM 해석

STEP 3의 F2 threshold를 읽어 TP·FP·FN·TN을 다시 정의한다.

- outer-validation TreeSHAP
- 전체·fold·기후지형유형·오류그룹별 SHAP 중요도
- SHAP 방향 요약
- FN과 FP 사례
- 대조군별 FP
- top-risk 산불과 나머지 산불의 변수 분포 비교

SHAP은 예측 기여도이며 인과효과가 아니다.

## 7. 검증 기준

- tuned LightGBM OOF는 17,045행이며 누락·중복·NaN이 없어야 한다.
- outer fold는 5개이고 score는 0~1 범위여야 한다.
- threshold 교차검증 감사에서 validation fold의 정답을 threshold 선택에 사용하지 않아야 한다.
- STEP 3과 STEP 4의 TP+FP+FN+TN 합계가 전체 OOF 행 수와 일치해야 한다.
- STEP 4의 재학습 OOF 예측이 STEP 2 저장 OOF와 일치해야 한다.
- 활성 파이프라인은 앙상블과 calibration 산출물을 입력으로 사용하지 않아야 한다.
