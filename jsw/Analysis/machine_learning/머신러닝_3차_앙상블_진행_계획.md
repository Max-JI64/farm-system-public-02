# 머신러닝 3차 앙상블 진행 계획

## 1. 기본 방향

3차의 목적은 1차에서 가장 성능이 높았던 모델을 단독으로 쓰는 것보다 더 높은 strict development OOF 성능을 만드는 것이다.

현재 기준선은 다음과 같다.

| 기준 | 모델 | AUPRC | 비고 |
|---|---|---:|---|
| 로지스틱 기준선 | `PLUS_LANDCOVER_RULES_ANOVA` | 0.2398 | Stage17 최종 비교 기준 |
| 1차 ML 최고 | `PLUS_LANDCOVER / HistGradientBoosting / raw` | 0.2984 | 현재 최고 모델 |
| 2차 ML 최고 | `PLUS_LANDCOVER_RULES_ANOVA_PROXY / HistGradientBoosting / raw` | 0.2200 | Optuna full 결과, 채택하지 않음 |

2차 Optuna는 성능 개선에 실패했으므로, 3차 앙상블의 주 재료는 1차 OOF 예측이다. 2차 예측은 다양성 확인용 보조 후보로만 사용한다.

lockbox test는 아직 열지 않는다. 3차도 development OOF 기준으로만 앙상블 후보를 선별한다.

## 2. 앙상블 원칙

앙상블은 여러 step으로 나누어 진행한다.

1. 먼저 단순하고 과적합 위험이 낮은 평균계열 앙상블을 확인한다.
2. 그 다음 제한적 weight search를 수행한다.
3. 마지막으로 meta-model stacking을 시도한다.
4. 최종 후보는 raw AUPRC만 보지 않고 0A hard-negative, top-risk capture, Brier/log loss, fold 안정성을 함께 본다.
5. 1차 최고 AUPRC 0.2984를 넘지 못하면 앙상블을 최종 채택하지 않는다.

앙상블의 성공 기준은 다음과 같다.

| 기준 | 값 | 해석 |
|---|---:|---|
| 최소 성공선 | AUPRC 0.3034 이상 | 1차 최고 대비 +0.005 |
| 강한 성공선 | AUPRC 0.3100 이상 | 최종 후보로 강하게 유지 |
| 0A 보조 기준 | 1차 최고 0A AUPRC 0.3069 이상 | 실제 hard-negative 개선 확인 |
| top 10% capture 기준 | 1차 최고 31.3% 이상 | 위험도 우선순위 성능 유지 또는 개선 |

### 3-2. 사용하지 않을 것

- lockbox test row
- Target을 직접 이용한 feature engineering
- fold 구분을 무시한 weight 최적화
- development 전체 성능으로 고른 weight를 같은 development 전체에 바로 평가하는 방식

앙상블 weight와 meta-model은 반드시 outer fold 내부 train 구간에서만 선택하고, outer validation fold에는 OOF 방식으로 적용한다.

## 4. 후보 예측 풀

### 4-1. 1차 주 후보

1차 raw 성능이 높고 로지스틱 기준선을 명확히 넘은 후보를 주 앙상블 재료로 둔다.

| priority | feature_set | model | score_type | AUPRC | 역할 |
|---:|---|---|---|---:|---|
| 1 | `PLUS_LANDCOVER` | `HistGradientBoosting` | raw | 0.2984 | 현재 최고, core anchor |
| 2 | `PLUS_LANDCOVER_RULES_ANOVA_PROXY` | `HistGradientBoosting` | raw | 0.2902 | 규칙 proxy 계열 대표 |
| 3 | `PLUS_LANDCOVER` | `LightGBM` | raw | 0.2878 | recall/ROC AUC 강점 |
| 4 | `PLUS_LANDCOVER_RULES_ANOVA_PROXY` | `RandomForest` | raw | 0.2826 | bagging 다양성 |
| 5 | `PLUS_LANDCOVER_RULES_ANOVA_PROXY` | `XGBoost` | raw | 0.2801 | 확률 지표와 AUROC 보조 |

### 4-2. 보조 후보

성능은 낮지만 다양성, calibration, 진단 목적이 있는 후보를 제한적으로 검토한다.

| 후보 | 이유 |
|---|---|
| `PLUS_LANDCOVER / HistGradientBoosting / sigmoid` | raw와 비슷한 ranking, 다른 확률 스케일 |
| `PLUS_LANDCOVER / LightGBM / sigmoid` | recall 높은 모델의 보정 score |
| `M1 / RandomForest / raw` | M1 진단 기준선, 다른 피처 구조 |
| `STAGE7_RECOMMENDED / HistGradientBoosting / raw` | 토지피복 제외 피처 구조 |
| `PLUS_LANDCOVER_RULES_ANOVA_PROXY / ExtraTrees / raw` | tree bagging 다양성 |

### 4-3. 제외 또는 보류 후보

- 2차 full Optuna 결과는 주 후보에서 제외한다. 1차 최고와 로지스틱 기준선을 모두 넘지 못했다.
- 1차에서 로지스틱 기준선보다 낮은 후보는 기본적으로 제외한다.
- calibrated score는 AUPRC가 낮아졌으므로 최종 ranking score 후보가 아니라 보정 비교용으로만 둔다.

## 5. Step3-A: 예측 후보 정리와 상관 진단

목적은 앙상블할 가치가 있는 후보를 선별하는 것이다.

작업:

1. 1차/2차 OOF prediction을 long format으로 정리한다.
2. 후보별 `샘플ID`, `outer_fold`, `Target`, `샘플유형`, `기후지형유형` 정합성을 확인한다.
3. 후보 score 간 Pearson/Spearman 상관을 계산한다.
4. fold별 AUPRC, 0A AUPRC, top-risk capture를 재계산한다.
5. 주 후보 5개와 보조 후보를 `candidate_registry`로 저장한다.

판단:

- AUPRC가 높지만 상관이 너무 높은 후보는 weight를 제한한다.
- 단독 AUPRC가 낮아도 상관이 낮고 0A 또는 top-risk가 좋은 후보는 보조 후보로 유지한다.

- `outputs/metrics/ml_stage3_candidate_correlation.csv`
- `outputs/metrics/ml_stage3_candidate_fold_metrics.csv`

## 6. Step3-B: 단순 앙상블

가장 먼저 과적합 위험이 낮은 방식부터 확인한다.

### 6-1. 평균 계열

비교할 방식:

- top 2 raw average
- top 3 raw average
- top 5 raw average
- rank average
- logit average
- geometric mean

예상 후보:

- `PL_HGB + PL_LGBM`
- `PL_HGB + RULES_HGB`
- `PL_HGB + PL_LGBM + RULES_XGB`
- `PL_HGB + RULES_HGB + RULES_RF + RULES_XGB`

### 6-2. 고정 weight 평균

성능 기반 고정 weight를 몇 가지 사전 정의한다.

예시:

| ensemble_id | 구성 |
---|---|
| `w_anchor_70_30` | 1차 최고 0.70 + 보조 0.30 |
| `w_anchor_50_lgbm_30_xgb_20` | HGB 0.50 + LightGBM 0.30 + XGBoost 0.20 |
| `w_top5_perf_weighted` | top5 AUPRC 비례 weight |
| `w_top5_sqrt_perf_weighted` | top5 sqrt(AUPRC 개선폭) weight |

선택 기준:

- 1차 최고 AUPRC 0.2984를 넘는지 확인한다.
- AUPRC가 비슷하면 top 10/20% capture와 0A AUPRC를 본다.
- 단순 앙상블이 1차 최고를 못 넘으면 복잡한 stacking으로 바로 가지 않고 후보 간 상관/오류 패턴을 먼저 확인한다.

산출물:

- `outputs/metrics/ml_stage3_simple_ensemble_comparison.csv`
- `outputs/predictions/ml_stage3_simple_ensemble_oof_predictions.csv`

## 7. Step3-C: 제한적 weight optimization

단순 평균에서 가능성이 보이면, nested CV 구조 안에서 weight를 최적화한다.

### 7-1. 방식

각 outer fold마다 outer-train 구간에서만 weight를 선택한다.

탐색 방법:

- non-negative weights
- sum(weights)=1
- candidate 수는 3~6개로 제한
- 한 모델 weight 상한 0.70
- AUPRC objective
- tie-breaker: 0A AUPRC, top 10% capture, Brier

탐색 알고리즘:

- coarse grid search
- random Dirichlet search
- coordinate refinement

Optuna는 여기서도 사용할 수 있지만, 모델 튜닝 때처럼 넓은 탐색을 하지 않는다. weight 수가 작으므로 grid/random search가 더 통제 가능하다.

### 7-2. 과적합 방지

- outer validation fold score를 weight 선택에 사용하지 않는다.
- fold마다 선택된 weight가 과도하게 흔들리면 채택하지 않는다.
- 1차 최고 모델 weight가 0.90 이상으로 몰리면 사실상 앙상블 효과가 없으므로 단독 모델 유지로 판단한다.
- 0A 성능이 크게 하락하면 전체 AUPRC가 조금 올라도 보류한다.

산출물:

- `outputs/metrics/ml_stage3_weight_search_trials.csv`
- `outputs/metrics/ml_stage3_selected_weights.csv`
- `outputs/metrics/ml_stage3_weighted_ensemble_comparison.csv`
- `outputs/predictions/ml_stage3_weighted_ensemble_oof_predictions.csv`

## 8. Step3-D: stacking meta-model

weight optimization보다 한 단계 복잡한 방식이다. 단순/weighted ensemble이 1차 최고에 근접하거나 넘는 경우에만 수행한다.

### 8-1. meta feature

meta-model 입력은 base model OOF score만 사용한다.

허용:

- base raw scores
- base rank-normalized scores
- logit-transformed scores
- outer fold indicator는 사용하지 않음

불허:

- 원본 feature 재사용
- Target 기반 파생 feature
- lockbox row

### 8-2. meta-model 후보

복잡한 모델은 피한다.

| meta-model | 목적 |
|---|---|
| LogisticRegression L2 | 가장 기본 stacking |
| LogisticRegression ElasticNet | 불필요 후보 weight 축소 |
| RidgeClassifier score 변환 | ranking 보조 비교 |
| Isotonic/rank calibration | monotonic 보정 |

트리 기반 meta-model은 3차 초반에는 쓰지 않는다. base score 수가 작고 development sample 수가 제한되어 과적합 위험이 크다.

### 8-3. 학습 구조

1. outer fold validation은 최종 OOF 평가로 보존한다.
2. outer-train 내부에서 meta-model hyperparameter를 선택한다.
3. outer-train 전체로 meta-model을 학습한다.
4. outer-validation에 적용해 OOF ensemble score를 만든다.

산출물:

- `outputs/metrics/ml_stage3_stacking_inner_tuning.csv`
- `outputs/metrics/ml_stage3_stacking_selected_configs.csv`
- `outputs/metrics/ml_stage3_stacking_comparison.csv`
- `outputs/predictions/ml_stage3_stacking_oof_predictions.csv`

## 9. Step3-E: calibration과 운영점

앙상블 후보가 정해진 뒤 calibration을 비교한다.

비교:

- raw ensemble score
- sigmoid calibration
- isotonic calibration
- calibrated_best

주의:

- 최종 ranking 비교는 raw AUPRC를 우선한다.
- calibration은 Brier/log loss와 운영 threshold 안정성 판단용이다.
- calibration 때문에 AUPRC가 크게 낮아지면 ranking score로 사용하지 않는다.

운영점은 로지스틱/1차와 동일하게 산출한다.

- fixed 0.50
- best-F1
- recall >= 0.50
- recall >= 0.70
- recall >= 0.90
- top 5/10/20% capture
- 0A/0B1/0B2 subgroup
- 기후지형유형 subgroup

산출물:

- `outputs/metrics/ml_stage3_calibration_comparison.csv`

## 10. Step3-F: 최종 후보 선정

3차 최종 후보는 다음 순서로 선정한다.

1. raw strict OOF AUPRC
2. 1차 최고 대비 AUPRC 개선폭
3. 0A hard-negative AUPRC
4. top 10%, top 20% capture
5. Brier/log loss
6. fold별 AUPRC 안정성
7. 모델 단순성

채택 조건:

- 1차 최고보다 AUPRC가 최소 +0.005 높으면 3차 후보로 채택한다.
- AUPRC 개선이 +0.005 미만이면, 0A 또는 top-risk가 명확히 좋아야 보조 후보로 유지한다.
- 어떤 앙상블도 1차 최고를 넘지 못하면 최종 모델은 1차 `PLUS_LANDCOVER / HistGradientBoosting / raw`로 유지한다.

## 13. 이후 단계

3차 앙상블에서 1차 최고를 넘는 후보가 나오면 다음 단계로 넘어간다.

- Step4: 최종 후보 1~3개에 대해 calibration 확정
- Step5: lockbox test 최초 평가
- Step6: 최종 보고서 표와 해석 정리

3차 앙상블이 실패하면 다음 단계는 lockbox가 아니라 2차 재설계 또는 피처 확장이다. 이 경우 1차 최고 모델을 임시 최종 모델로 유지한다.
