# 머신러닝 1차 진행 계획 v2

## 1. 기본 방향

이번 1차 머신러닝의 목적은 로지스틱과 단순히 같은 조건으로 공정 비교만 하는 것이 아니다.
로지스틱 Step17까지의 최종 결과와 진단을 바탕으로, strict CV 기준에서 로지스틱보다 높은 예측 성능을 내는 ML 후보를 만드는 것이 목적이다.

따라서 진행 구조는 다음처럼 잡는다.

1. 로지스틱 초기 구조인 `M1`, `M2`, `M3`를 다시 돌려 ML에서도 FA·캐나다지수 효과가 같은 방향인지 확인한다.
2. 로지스틱 최종 성능 개선 과정에서 효과가 있었던 EDA 파생, 토지피복, FWI 중심 피처를 ML 주 실험에 반영한다.
3. 모든 피처셋에 모든 ML 모델을 적용한다.
4. 결과표에서는 특정 모델이 안 보이는 일이 없도록 전체 조합표를 top-N으로 자르지 않는다.

`M1/M2/M3`는 “혹시 모르니 다시 비교하는 확인 단계”이지, 1차 ML의 최종 주 실험 전체가 아니다.

## 2. 로지스틱 최종 결과에서 가져올 기준

로지스틱 최종 결론은 다음과 같이 반영한다.

| 로지스틱 결과 | ML 1차 반영 |
|---|---|
| `M1`과 `M2`는 거의 같아 FA 추가 효과가 작았다 | ML에서도 `M1/M2/M3`를 확인하되, FA-only류를 주 실험으로 과대 배치하지 않는다 |
| D-1 캐나다 지수는 `M3` 대비 성능을 올렸다 | 캐나다 지수 포함 세트를 주 후보로 유지한다 |
| Stage7 EDA 파생 피처가 성능을 올렸다 | `STAGE7_RECOMMENDED`를 ML 주 피처셋에 포함한다 |
| 토지피복은 strict CV에서도 성능을 올렸다 | `PLUS_LANDCOVER`를 ML 주 피처셋에 포함한다 |
| 임상도는 매칭 28건이라 정보량이 작다 | 1차 주 실험에서는 제외하고 2차 이후 민감도 후보로 둔다 |
| 최종 성능 비교용 로지스틱은 `PLUS_LANDCOVER_RULES_ANOVA` | ML 개선폭은 이 모델의 Stage17 성능 대비로 계산한다 |
| 해석용 안정 모델은 `FINAL_REDUCED_WITH_FWI` | compact/robust ML 참고 피처셋으로 별도 비교한다 |

1차부터 “로지스틱보다 좋아질 것”을 전제로 진행한다.
만약 1차 raw screening에서 로지스틱 기준선을 못 넘으면 그것을 결론으로 끝내지 않고, 어떤 피처셋·모델군이 병목인지 진단해 2차 튜닝으로 넘긴다.

## 4. 피처셋 구성

피처셋은 두 그룹으로 나눈다.

### 4-1. 확인용 M1/M2/M3

로지스틱 초기 비교와 같은 구조를 ML에서도 확인한다.

| feature_set | 구성 | 목적 |
|---|---|---|
| `M1` | 날씨·공간 + FA 요인점수 + D-1 캐나다 지수 | ML에서도 FA 추가 효과가 있는지 확인 |
| `M2` | 날씨·공간 + D-1 캐나다 지수 | 로지스틱 초기 주 구성과 비교 |
| `M3` | 날씨·공간 | 캐나다 지수 제거 시 성능 하락 확인 |

이 세트는 `feature_manifest.json`의 `model_sets`를 그대로 사용한다.

### 4-2. 로지스틱 최종 결과 기반 ML 주 실험

| feature_set | 구성 | 목적 |
|---|---|---|
| `STAGE7_RECOMMENDED` | 로지스틱 Stage7 추천 EDA 파생 피처 포함 | EDA 피처가 ML 비선형 모델에서 더 크게 먹히는지 확인 |
| `PLUS_LANDCOVER` | `STAGE7_RECOMMENDED` + 토지피복 | strict CV에서 로지스틱 성능을 올린 공간 피처를 ML에 반영 |
| `PLUS_LANDCOVER_RULES_ANOVA_PROXY` | `PLUS_LANDCOVER` + Stage9 규칙/선택 피처 재현 | 성능 비교용 로지스틱 `PLUS_LANDCOVER_RULES_ANOVA`에 가장 가까운 ML 입력 |
| `FINAL_REDUCED_WITH_FWI_PROXY` | Stage16 해석용 축소 모델의 핵심 변수 + FWI | compact/robust ML 참고 후보 |

1차 주 승자는 이 그룹과 M1/M2/M3를 모두 포함한 전체 조합에서 고르되, 보고서에는 “확인용 M세트”와 “최종결과 기반 주 실험”을 구분해 쓴다.

## 5. 후보 모델

모든 모델은 모든 피처셋에 적용한다.
피처셋마다 사용하는 모델이 달라지지 않는다.

| 모델 | 1차 설정 | 불균형 처리 |
|---|---|---|
| `RandomForest` | bagging baseline | `class_weight=None`, `balanced_subsample` |
| `ExtraTrees` | randomized tree ensemble | `class_weight=None`, `balanced` |
| `HistGradientBoosting` | sklearn histogram boosting | `class_weight=None`, `balanced` |
| `XGBoost` | gradient boosting tree | `scale_pos_weight=1`, `auto` |
| `LightGBM` | leaf-wise boosting | `class_weight=None`, `balanced` |
| `CatBoost` | ordered boosting | `auto_class_weights=None`, `Balanced` |

모델 누락 방지:

- 실행 시작 시 `sklearn`, `xgboost`, `lightgbm`, `catboost` import 가능 여부를 `dependency_audit`에 저장한다.
- 어떤 모델이 import 실패하면 결과표에서 삭제하지 않고 `run_status=NOT_RUN`, `reason`을 남긴다.
- summary의 상위 후보표와 별개로 전체 조합표를 반드시 제공한다.

## 7. 학습 구조

각 `feature_set × model` 조합은 같은 strict nested CV를 사용한다.

1. outer fold의 validation fold를 OOF 평가 구간으로 둔다.
2. outer-train 내부 inner CV에서 모델별 기본 config와 불균형 옵션을 선택한다.
3. 선택된 config로 outer-train 전체를 재학습한다.
4. outer-validation OOF raw score를 저장한다.
5. 모든 outer fold를 합쳐 development OOF 성능을 계산한다.

SMOTE는 1차에서 사용하지 않는다.
공간·시간·기상 조합을 임의 합성하면 실제 존재하지 않는 관측 단위가 생기기 때문이다.

## 8. Calibration

1차 승자 판단은 raw AUPRC 기준으로 한다.
다만 최종 운영에서는 확률 품질도 중요하므로 calibration을 보조로 산출한다.

calibration 대상:

- 전체 raw AUPRC 상위 3개 조합
- `M1`, `M2`, `M3` 각각의 최고 조합
- 로지스틱 최종 기반 주 실험 그룹의 최고 조합

비교 score:

- `raw`
- `sigmoid`
- `isotonic`
- `calibrated_best`

calibration 결과는 raw 순위 성능표와 분리해서 해석한다.

## 10. 로지스틱 기준선과 목표

주 비교 기준은 Stage17 성능 비교용 대표 로지스틱이다.

| 항목 | 값 |
|---|---:|
| 기준 모델 | `PLUS_LANDCOVER_RULES_ANOVA` |
| AUPRC | 0.239835 |
| ROC AUC | 0.776760 |
| Brier | 0.076969 |
| Log loss | 0.265887 |
| Best-F1 | 0.304745 |

ML 1차의 최소 목표는 이 로지스틱 기준선보다 높은 strict OOF AUPRC다.
하지만 단순히 `+0.001` 높이는 것으로 끝내지 않고, 2차 튜닝 후보를 만들기 위해 다음을 함께 본다.

- raw AUPRC 개선폭
- `Target_1 vs Target_0A` AUPRC
- top 10%, 20% capture
- Brier/log loss
- fold 안정성

## 11. 1차 판단 기준

1차 전체 승자는 strict development OOF raw AUPRC가 가장 높은 조합으로 정한다.

동률 또는 차이가 `0.005` 이내면 다음 순서로 판단한다.

1. Brier와 log loss
2. `Target_1 vs Target_0A` AUPRC
3. top 10%, 20% capture
4. fold 안정성
5. calibration 이후 확률 품질

로지스틱 기준선을 넘지 못한 경우에도 “ML이 안 된다”로 결론내지 않는다.
그 경우 1차 결과는 병목 진단으로 보고, 2차에서 Optuna 튜닝과 피처 확장을 진행한다.

## 13. 2차로 넘길 후보

2차 Optuna 튜닝 후보는 최소 다음을 포함한다.

- 전체 1위 조합
- 로지스틱 최종 기반 주 실험 그룹의 1위 조합
- `M1`, `M2`, `M3` 중 예상과 다른 결과가 나온 조합
- XGBoost, LightGBM, CatBoost 중 전체 1위와 AUPRC 차이가 `0.01` 이내인 조합

2차에서는 하이퍼파라미터 탐색, feature interaction 확장, calibration 고정 전략을 진행한다.
