# 머신러닝 7차 최종모델 해석/오류분석 계획

## 1. 목적

- Step6에서 고정한 최종 모델 `model_level_top5_geometric_mean / raw`의 작동 특성을 해석한다.
- 성능 개선이나 후보 재선택이 아니라, 최종 보고서에 넣을 설명 근거를 만든다.
- lockbox 결과는 사후 튜닝에 사용하지 않고 오류 유형, risk decile, base model agreement를 해석하는 데만 사용한다.

## 2. 입력

- 최종 OOF 예측: `outputs/predictions/ml_stage4_final_candidate_oof_predictions.csv`
- 최종 lockbox 예측: `outputs/predictions/ml_stage5_lockbox_final_predictions.csv`
- base model OOF 예측: `outputs/predictions/ml_stage35_base_model_oof_predictions.csv`
- base model lockbox 예측: `outputs/predictions/ml_stage5_lockbox_base_model_predictions.csv`
- full-development base model manifest: `outputs/metrics/ml_stage35_final_model_manifest.csv`
- Step6 최종 의사결정: `outputs/metrics/ml_stage6_final_model_decision.csv`

## 3. 분석 항목

1. Score decile 분석
   - development OOF와 lockbox를 각각 최종 score 기준 10분위로 나눈다.
   - 각 decile의 양성률, 누적 capture, lift를 계산한다.

2. Threshold 오류분석
   - Step6 권장 threshold `recall_ge_0.70`을 고정 적용한다.
   - TP/FP/FN/TN 구성과 기후지형유형, 샘플유형별 분포를 산출한다.

3. Base model agreement 분석
   - 5개 base model score의 평균, 표준편차, 범위, threshold 이상 모델 수를 계산한다.
   - base model 간 상관관계와 합의도별 양성률을 산출한다.

4. Native feature importance
   - full-development로 학습된 base model 중 `feature_importances_`를 제공하는 모델만 사용한다.
   - one-hot 이후 transformed feature importance를 원 피처 단위로 합산한다.
   - 이 값은 모델 내부 중요도이므로 인과 효과로 해석하지 않는다.

## 4. 출력

- `outputs/metrics/ml_stage7_score_decile_analysis.csv`
- `outputs/metrics/ml_stage7_threshold_error_profile.csv`
- `outputs/metrics/ml_stage7_base_model_agreement.csv`
- `outputs/metrics/ml_stage7_base_model_correlation.csv`
- `outputs/metrics/ml_stage7_native_feature_importance.csv`
- `outputs/metrics/ml_stage7_top_error_samples.csv`
- `outputs/metrics/ml_stage7_validation_checks.csv`
- `outputs/ml_stage7_final_model_diagnostics.md`
- `머신러닝_7차_최종모델_해석_결과.md`

## 5. 검증

- development OOF 13,632행, lockbox 3,413행을 유지한다.
- 최종 score와 base model score에 NaN/inf가 없는지 확인한다.
- Step6 권장 threshold가 정상적으로 읽히는지 확인한다.
- native feature importance를 최소 1개 base model에서 산출했는지 확인한다.
