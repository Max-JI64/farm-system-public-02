# 머신러닝 6차 최종보고서 정리 계획

## 1. 목적

- 1차~5차 머신러닝 결과를 최종 보고서에 바로 사용할 수 있는 형태로 정리한다.
- 새 모델 학습이나 추가 튜닝은 하지 않는다.
- development OOF와 lockbox test 결과를 명확히 분리해서, lockbox를 이용한 사후 선택으로 해석되지 않게 한다.

## 2. 입력 산출물

- 로지스틱 최종 비교표: `../logistic/outputs/tables/stage17_ml_comparison_metrics.csv`
- 1차 ML 스크리닝: `outputs/metrics/ml_stage1_v2_all_model_comparison.csv`
- 2차 Optuna 튜닝: `outputs/metrics/ml_stage2_model_comparison.csv`
- 4차 최종 후보 선택: `outputs/metrics/ml_stage4_final_candidate_selection.csv`
- 5차 lockbox 평가:
  - `outputs/metrics/ml_stage5_lockbox_model_comparison.csv`
  - `outputs/metrics/ml_stage5_oof_vs_lockbox_comparison.csv`
  - `outputs/metrics/ml_stage5_lockbox_fixed_thresholds.csv`
  - `outputs/metrics/ml_stage5_lockbox_top_risk_capture.csv`
  - `outputs/metrics/ml_stage5_lockbox_subgroup_metrics.csv`
  - `outputs/metrics/ml_stage5_lockbox_base_model_metrics.csv`
  - `outputs/metrics/ml_stage5_validation_checks.csv`

## 3. 최종 모델 정의

- 최종 보고서용/운영 threshold용 모델은 `model_level_top5_geometric_mean / raw`로 둔다.
- `model_level_top5_rank_average / raw`는 순위화 진단 보조 결과로 유지한다.
- 이유:
  - Step4 development OOF에서 AUPRC가 1차 단일 ML 최고보다 0.005 이상 개선되었다.
  - Brier/log loss가 안정적이므로 확률 점수와 threshold 운영에 사용할 수 있다.
  - Step5 lockbox에서도 rank-average보다 AUPRC와 확률 지표가 더 좋았다.

## 4. 정리 방식

1. 로지스틱 기준선, 1차 단일 ML 최고, 2차 Optuna 최고, Step4 최종 후보, Step5 lockbox 후보를 하나의 비교표로 묶는다.
2. 최종 probability score의 development OOF와 lockbox 운영 threshold 성능을 정리한다.
3. 최종 probability score의 top 5/10/20% capture를 정리한다.
4. hard-negative 및 기후지형 하위그룹 성능을 정리한다.
5. 최종 선택 근거와 해석상 주의점을 Markdown으로 작성한다.

## 5. 해석 원칙

- lockbox 결과는 최초 평가 결과로만 보고, 추가 튜닝이나 후보 재선택에 사용하지 않는다.
- 로지스틱 지표는 development OOF 기준선이므로, lockbox 결과와 직접 같은 테스트셋 성능처럼 표현하지 않는다.
- lockbox 성능이 development OOF보다 크게 높으므로, “일반화 성능이 OOF보다 높다”가 아니라 “고정 후보가 lockbox에서 강한 성능을 유지했다”로 표현한다.

## 7. 검증

- 필수 입력 파일이 모두 존재하는지 확인한다.
- 최종 probability score와 ranking score가 development OOF와 lockbox에 모두 존재하는지 확인한다.
- Stage5 validation check가 모두 통과했는지 확인한다.
- 최종 비교표의 핵심 지표에 NaN/inf가 없는지 확인한다.
